C++ · Module 07 · Templates

Generic code

Write a function or a class once and have it work for every type: swap, min, max, iter, then an Array<T>. What the subject asks for, and the traps the compiler has in store for you.

subject: en.subject (1).pdf · version 10.1 · c++ -Wall -Wextra -Werror -std=c++98

01

The module in brief

Module 07 introduces templates. Instead of writing one swap for int, another for std::string, another for your own classes, you write a single model: the compiler builds the version it needs for each type you use.

Three exercises, each richer than the last. ex00: three small functions, swap, min and max. ex01: an iter function that calls a function on every element of an array, whether the array is const or not. ex02: an Array<T> class, a dynamic array with a deep copy and access checked by operator[].

There is little code to write, but many compilation details: where to put the code, which type the compiler deduces, what is const. That is where this course helps.

📖

The page numbers in parentheses, like (p. 8), are the ones printed at the bottom of the subject's pages (version 10.1): the PDF page number is one higher. Keep the PDF open next to this page: this course explains the subject, it does not replace it. The compiler messages quoted come from Apple clang 17 on macOS (c++ -std=c++98 -Wall -Wextra -Werror); g++ on your school machine may word them differently: to check.

🧠

The subject devotes a chapter to AI (p. 6-7): reason first, and do not ask for ready-made answers. This course explains the concepts and the traps; the code of your files is yours to write.

03

Templates, demystified

A model, not a function

A function template is not a function: it is a model. The compiler only produces code from it when it is called with a specific type. Here is an invented example, unrelated to the subject:

twice.cpp · an example model
template <typename T>
T twice(T x)
{
	return x + x;
}

int main()
{
	std::cout << twice(21) << std::endl;    // T = int
	std::cout << twice(1.5) << std::endl;   // T = double
	return 0;
}

The compiler deduces T by looking at the argument: 21 is an int, 1.5 a double. Here it builds two distinct functions. You can see them in the object file (observed with clang on macOS):

terminal · addresses removed
$ c++ -std=c++98 -c twice.cpp -o twice.o
$ nm -C twice.o | grep twice
T double twice<double>(double)
T int twice<int>(int)

One version per type used, and only those. Two consequences: the compiler must see the body of the template at the point of the call, and an error in the body only appears when a version is built. A template that is never called is only half checked: test it with several types.

Why everything goes in the .hpp

Try putting the body in a .cpp, as for an ordinary function: the .hpp holds only the declaration, the .cpp the body. Each file compiles without error. But main.cpp asks for swap<int> and only sees the declaration; the .cpp has the body but nobody there asks for swap<int>, so it builds nothing. What remains is a call to a function that exists nowhere:

terminal · link error (macOS)
Undefined symbols for architecture arm64:
  "void swap<int>(int&, int&)", referenced from:
      _main in wmain.o
ld: symbol(s) not found for architecture arm64

That is why the subject requires templates to be defined in the headers (p. 8). On Linux the linker message is worded differently ("undefined reference to").

typename or class?

In template <typename T> you may write class instead of typename: it is equivalent here (both versions compile). Pick one and stick to it throughout the module.

The :: in the subject's calls

In the subject's main (p. 9), everything is written ::swap(a, b), ::min(a, b). A :: in front of a name means "look in the global namespace, and nowhere else": so it is your swap, not the one from std. Without it, the lookup may also find the standard library version, and the compiler refuses to choose. Checked with clang and libc++, without using namespace:

terminal · min(c, d) on two std::string, without ::
error: call to 'min' is ambiguous
note: candidate function [with _Tp = std::string]
note: candidate function [with T = std::string]

The compiler also looks in the namespace of the arguments (std, for a std::string): it finds std::min in addition to yours. With using namespace std; (forbidden in this module, p. 4), even a call on int becomes ambiguous. With the :: there is no ambiguity. This behavior comes from libc++; to check with your school's compiler.

04

ex00 · swap, min, max"Start with a few functions" (subject, p. 8)

In plain words. Three function templates. swap exchanges the values of two parameters and returns nothing. min returns the smaller of the two values, max the greater, and if they are equal, both return the second one (p. 8). The two arguments must have the same type, and that type must support all the comparison operators (p. 8).

Files to submit (p. 8): Makefile, main.cpp, whatever.{h, hpp}, in ex00/.

ex00/whatever.hpp · skeleton
#ifndef WHATEVER_HPP
#define WHATEVER_HPP

template <typename T>
void swap(T &a, T &b) { /* up to you */ }

template <typename T>
const T &min(const T &a, const T &b) { /* up to you */ }

template <typename T>
const T &max(const T &a, const T &b) { /* up to you */ }

#endif

The names swap, min, max are imposed; the parameter names are free. The subject does not fix the return type of min and max: returning a const reference to one of the arguments avoids a copy, and lets you check which argument came out by comparing addresses (advice, not a rule).

The case of equal values

This is the detail that makes people fail. Depending on how you write the comparison, you return the first or the second argument when both are equal. With int you will never see the difference: two 42 are indistinguishable. To see it, test with a type whose comparison looks at only part of the object. The demo below does that: each variable carries a key, the only thing compared, and a label that lets you recognize the object returned.

For your own tests, a small type is enough (a test, not a solution):

main.cpp · a test type
struct Item
{
	int			key;
	std::string	label;
	bool operator<(const Item &o) const { return key < o.key; }
	bool operator>(const Item &o) const { return key > o.key; }
};

With two Item of key 5 and different labels, look at the label returned by ::min and by ::max: it is the one of the second argument (checked by compiling).

Demo: two variables, each with a key (compared) and a label (ignored), and three calls ::swap, ::min, ::max. Control cases:

a = 2, b = 3: after ::swap(a, b), a = 3, b = 2; min(a, b) = 2; max(a, b) = 3.

c = chaine1, d = chaine2: after ::swap(c, d), c = chaine2, d = chaine1; min(c, d) = chaine1; max(c, d) = chaine2.

Equal keys (5 and 5), labels "first" and "second": min and max both return the second one.

The expected result

The subject gives a main and the output it must produce (p. 9). Its calls begin like this:

subject's main (p. 9) · beginning
int a = 2;
int b = 3;
::swap( a, b );
std::cout << "a = " << a << ", b = " << b << std::endl;

and the announced output is:

announced output (p. 9)
a = 3, b = 2
min(a, b) = 2
max(a, b) = 3
c = chaine2, d = chaine1
min(c, d) = chaine1
max(c, d) = chaine2
⚠️

The subject is not consistent to the character. In the main on p. 9, the messages are written "min( a, b ) = " (with spaces inside the parentheses), while the announced output shows min(a, b) = 2. Compiled as is, the subject's main prints the form with spaces; the values are the right ones. To check with your evaluator if a character-by-character comparison worries you.

🧪

What your main should test. The subject's main (int then std::string); a type other than the subject's (double, char); two equal values with a key-and-label type, to see that the second one is returned.

ex01 · iter"Iter" (subject, p. 10)

In plain words. A function template iter with three parameters, returning nothing (p. 10): (1) the address of an array, (2) its length, "passed as a const value", (3) a function called on every element. It must work with any type of array, and the third parameter can be an instantiated function template. The function passed may take its argument by const or non-const reference, "depending on the context".

Files to submit (p. 10): Makefile, main.cpp, iter.{h, hpp}, in ex01/. The subject also asks for a main.cpp with your tests, complete enough to produce a test executable.

The three parameters

1The address of the array: a T * pointer. The compiler deduces T from the array. For a const int[3] it deduces T = const int: that is how the same template accepts const arrays.
2The length, const. A const on a by-value parameter does not change the signature (checked: void g(std::size_t) and void g(const std::size_t) are the same function); it only forbids you to modify the length inside the function. If you choose int instead of std::size_t (from <cstddef>), compare it with a counter of the same signedness: otherwise -Wsign-compare becomes an error with -Werror.
3The function. This is the hard parameter: its type must accept an ordinary function, an instantiated template like print<int>, a const or non-const reference, on a const or non-const array.

Three ways to type the third parameter

"Think carefully about how to support both const and non-const elements" (p. 10): this is the key sentence of the exercise. There are at least three candidates. A: a second template parameter F for the function, whatever it is. B: a function pointer void (*)(T &). C: two overloads, one with T * and void (*)(T &), the other with const T * and void (*)(const T &). The demo compiled all of them, on both arrays, with the three kinds of function and the three ways of passing it.

Demo: "does the compiler accept this call?". Each verdict comes from a program compiled with Apple clang 17 (c++ -std=c++98 -Wall -Wextra -Werror). Control cases:

const int tab[3] and a function void f(int &): ✗ (with signature A: error: binding reference of type 'int' to value of type 'const int' drops 'const' qualifier).

int tab[3] and a function void f(const int &): ✓ with signatures A and C, ✗ with B.

An instantiated template f<int> (const T & function): ✓ with signature A, on both arrays.

What the demo's table shows, with Apple clang:

AGeneric parameter F. The most flexible: ordinary function, instantiated template, const or non-const reference, by value. It only refuses what the body refuses (giving a const to a function that modifies it) and a template name alone.
Bvoid (*)(T &). Only one shape of function gets through. A const array gives T = const int on one side and int on the other: conflict. A const T & function on a modifiable array: conflict too.
CTwo overloads. A T & function gets through on a modifiable array, a const T & function on both. A by-value function is refused, except in a curious case of a template name alone.
💡

The third parameter can be an instantiated template (p. 10). iter(tab, 3, print<int>) passes the address of the version of print built for int. Writing iter(tab, 3, print), the template name without <int>, fails with signature A: couldn't infer template argument 'F'. You will also see cases where stricter signatures manage to pick the right version on their own; better to write <int>.

There is no single answer: choose a signature, test the subject's cases (const array or not, const reference or not, instantiated template), and be able to explain what your signature refuses.

ex01/main.cpp · test ideas
template <typename T>
void print(const T &x) { std::cout << x << " "; }

int         numbers[3] = {1, 2, 3};
const int   fixed[3]   = {4, 5, 6};

iter(numbers, 3, print<int>);   // modifiable array, instantiated template
iter(fixed, 3, print<int>);     // const array
iter(numbers, 0, print<int>);   // length 0: nothing must happen

Add an array of another type (std::string, double) and a function that modifies the elements. The subject imposes no output for this exercise: your main only has to show that everything works.

ex02 · Array"Array" (subject, p. 11)

In plain words. A class template Array<T> that holds elements of type T (p. 11): a constructor with no parameter (empty array), a constructor with an unsigned int n (n elements "initialized by default"), a copy by constructor and by operator= after which the original and the copy are independent, access through [] that throws an std::exception when out of bounds, and a member function size().

Files to submit (p. 11): Makefile, main.cpp, Array.{h, hpp}, and optionally Array.tpp, in ex02/.

ex02/Array.hpp · skeleton
#ifndef ARRAY_HPP
#define ARRAY_HPP

#include <cstddef>
#include <exception>

template <typename T>
class Array
{
	private:
		T				*_data;
		unsigned int	_size;

	public:
		Array();                                // empty array
		Array(unsigned int n);                  // n elements "by default"
		Array(const Array &other);              // deep copy
		Array &operator=(const Array &other);   // deep copy
		~Array();

		T				&operator[](unsigned int i);
		const T			&operator[](unsigned int i) const;
		unsigned int	size() const;

		class OutOfBoundsException : public std::exception
		{
			public:
				virtual const char *what() const throw();
		};
};

#include "Array.tpp"   // optional: the definitions may also stay here

#endif

Only Array, size(), [] and the unsigned int type of the constructor come from the subject; the name and number of attributes and the name of the exception are free. As in the whole module, the class is in Orthodox Canonical Form (p. 4): default constructor, copy constructor, operator=, destructor.

Constructing: new[], "by default", no allocating ahead

The subject imposes operator new[] and forbids preventive allocation (reserving room in advance, p. 11): Array(n) allocates exactly n elements, and your program "must never access non-allocated memory". "Initialized by default": the subject suggests trying int * a = new int(); then displaying *a (p. 11). Here is what clang gives on macOS:

terminal · clang, c++98
new int()       -> 0
new int[5]()    -> 0 0 0 0 0
new string[3]() -> [][][]
new int[5]      -> -1431655766 -1431655766 ...   (with MallocPreScribble=1)

The empty parentheses () make the difference: with them, an int is 0 and a std::string is empty (the default constructor of T is called). Without them, the int values are indeterminate: reading them is undefined behavior. A clean value may come out by luck; the macOS environment variable MallocPreScribble=1 fills fresh memory with a pattern and shows the truth (-1431655766 is 0xAAAAAAAA).

Consequence: a T without a default constructor cannot be stored. Checked: Array<NoDefault> a(3); gives error: no matching constructor for initialization of 'NoDefault[]'. However, Array<NoDefault> a; alone compiles: the compiler only builds the member functions the program uses.

Copying: deep, for real

"Modifying either the original array or its copy after copying musn't affect the other array" (p. 11): a deep copy, in two places, the copy constructor and operator=. If you let the compiler generate the copy, it copies the pointer _data: both arrays share the same cells, and each destructor does delete[] on the same address. With clang on macOS the program dies with Trace/BPT trap: 5; this is undefined behavior, the symptom changes from system to system. The demo shows both versions side by side.

For operator=, think about three things: self-assignment (a = a: if you free the old array before copying, you copy from freed memory); the old content (to be freed, otherwise a leak); the size (the target may have a different size). In a test, clang refuses an a = a; written as is (-Wself-assign-overloaded with -Wall): go through a reference, Array<int> &alias = a; a = alias;.

Accessing: [] in two versions, and an exception

operator[] returns a reference T &, otherwise a[0] = 5 does not compile (expression is not assignable). You need a second, const one, returning const T &: without it, an array received as const Array<int> & cannot be read (no viable overloaded operator[] for type 'const Array<int>'). Both check the index: if it is out of bounds, they throw an exception (p. 11). The subject writes "an std::exception is thrown": a nested class that inherits from std::exception is one, and catch (std::exception &e) catches it (checked); throwing std::exception() directly works too. In C++98, what() keeps the signature virtual const char *what() const throw();.

The parameter is an unsigned int: a negative index is converted to it. a[-1] becomes a[4294967295] (checked), hence "out of bounds" and your test catches it, provided you compare with >= against the size without converting to int. Mind your test loops too: for (int i = 0; i < a.size(); i++) does not compile with -Werror (comparison of integers of different signs); use an unsigned int.

Measuring: size() and the .tpp file

size() takes no parameter and must not modify the instance (p. 11): it is const. Without const, an array received as const Array<int> & cannot call size() ('this' argument to member function 'size' has type 'const Array<int>', but function is not marked const).

About the optional Array.tpp file (p. 11): it receives the definitions of the member functions, your Array.hpp includes it on the last line before the #endif, and the Makefile does not compile it (it is not a .cpp). For the nested exception: a member of a template remains "templated", so what() can live in the .tpp; a free-standing exception class defined in the .hpp with a body would be an implementation in a header (rule on p. 4): to check with your evaluator.

Demo: two arrays a and b shown as cells, with a "shallow copy (wrong)" mode and a "deep copy" mode. Control cases:

Array<int>(5): 5 cells, all 0 (new int[5]()).

Deep copy then modifying the copy: the original does not change. Shallow copy: both arrays change together, and the end of scope reports a double free.

a[5] on 5 cells: std::exception exception. size() of an empty array: 0.

🧪

What your main should test. An empty array (size() is 0, [0] throws); Array<int>(5) with its five zeros; an Array<std::string>; a copy then a modification of the copy, with the original staying put; an assignment, including onto an array that is already filled; an index equal to the size and a negative index; reading through a const Array<T> &; no leak.

07

Step by step

An order that limits back and forth: each exercise reuses the idea of the previous one.

1Prepare the ground. One directory per exercise (ex00/, ex01/, ex02/, p. 3), a Makefile that compiles with -Wall -Wextra -Werror -std=c++98 and does not relink, headers with include guards. No using namespace, no <algorithm>.
2ex00. Write swap, min, max in whatever.hpp. Compile first with the subject's main (p. 9) and compare the values. Then add a key-and-label type to check the equal-values case.
3ex01, one case at a time. Make iter work with a modifiable int[] and a function taking a reference. Then the const array, the const reference, the instantiated template, another element type, a zero length. Each case that breaks teaches you something about your signature.
4ex02, skeleton first. Declare the class, the default constructor and size(): an empty array that compiles. Add Array(n) and [] with the bounds check and the exception.
5The copy. Copy constructor, then operator= (self-assignment, old content, new size). Test by modifying the copy, then the original.
6The const overload. Add the second operator[] and test it with a function that receives a const Array<int> &.
7Final check. A test with an Array<std::string>, then memory: leaks --atExit -- ./array on macOS (it prints "0 leaks" when everything is freed), valgrind on Linux. Run make twice: the second run must do nothing. Check the names of files and directories (p. 12).
08

Classic pitfalls

⚠️

A template defined in a .cpp. Every file compiles, then linking fails: Undefined symbols … "void swap<int>(int&, int&)" on macOS (checked). The body must be visible where the template is called: in the .hpp (p. 8), or in a .tpp it includes (p. 11).

⚠️

min or max returning the first one when the values are equal. The subject wants the second (p. 8). It depends on how you write the test: on a key-and-label type, a test written "backwards" returns the first label (checked by compiling). With int you will never see it: test with a type where the difference shows.

⚠️

A swap without a temporary value. Two assignments, a = b; b = a;, overwrite the first value: with 2 and 3 you get a = 3, b = 3 (checked). You must keep one of the two values before overwriting it.

⚠️

Calling without ::, or with two types. min(c, d) on std::string is ambiguous with std::min (clang, libc++). ::min(a, 3.5) with an int and a double does not compile: both arguments must have the same type (p. 8).

⚠️

An iter that refuses a const array. If the third parameter is typed void (*)(T &), a const int[3] does not get through: T is const int on one side, int on the other. And passing a template name without <int> fails with a generic parameter F. The demo shows each case.

⚠️

A non-const length (ex01). The subject wants it "passed as a const value" (p. 10). It does not change the signature, but your evaluator will look at it. And an int compared with a std::size_t counter does not compile with -Werror (-Wsign-compare).

⚠️

Copying the pointer instead of the cells. Shallow copy: two Array share the same _data, and the second destructor does a delete[] on an address already freed. With clang on macOS the program dies with Trace/BPT trap: 5. The subject requires the copy to be independent (p. 11).

⚠️

An operator= that forgets self-assignment. If you free the old array before copying, a = a copies from freed memory. One test prints "0 0 0" instead of "1 2 3", and pattern values with MallocScribble=1. Test through a reference: clang refuses a literal a = a;.

⚠️

Allocating ahead, or going out of bounds. Preventive allocation is forbidden and the program must never access non-allocated memory (p. 11). An operator[] with no bounds check reads or writes outside the array: undefined behavior, no exception.

⚠️

Forgotten const. A non-const size() cannot be called on a const array; a single non-const operator[] cannot be read on a const array; an operator[] that returns T by value does not allow a[0] = 5. All three errors were reproduced with clang.

⚠️

The negative index. a[-1] is converted to unsigned int: 4294967295 with 32 bits. Your bounds test must stay correct for this value: it is ≥ the size, so an exception.

⚠️

A T without a default constructor. Array<T>(n) then does not exist: new T[n]() does not compile. The constructor with no parameter does compile (checked) since the body of Array(n) is not built.

09

How I did it

I followed the subject's order. For ex00, a single header with three functions that take and return const references; my main reuses the subject's, then adds double, char and two equal values whose address I compare with the second argument's. For ex01, iter has two template parameters, the element type and the function type: that is what accepts a const array, a reference and an instantiated template like print<int>. For ex02, Array.hpp includes Array.tpp at the end. The constructor with n elements uses new T[n](); the copy is deep; operator= builds the new buffer before freeing the old one and guards against self-assignment; both operator[] throw the same nested exception. My test compares an Array with a mirror array of 750 integers, plus the empty case, a copy and an out-of-bounds access.

📌 Takeaways (defense checklist)

  • ✓
    Templates go in headers. "Templates must be defined in the header files" (p. 8); it is the only implementation tolerated in a .hpp (p. 4). A .cpp gives a link error.
  • ✓
    The compiler builds one version per type used. T is deduced from the arguments; two arguments of different types are rejected.
  • ✓
    Why ::? It limits the lookup to the global namespace: your swap, not the one from std (ambiguity otherwise). And <algorithm> is forbidden before module 08.
  • ✓
    Equal values: the second. min and max return the second argument (p. 8); a const reference lets you check it.
  • ✓
    iter: address, const length, function (p. 10). It must accept const or non-const elements, a const or non-const reference, an instantiated template (print<int>). Be able to say what your signature refuses.
  • ✓
    Array: new[], no preventive allocation (p. 11). new T[n]() initializes by default (0 for an int); without (), int values are indeterminate.
  • ✓
    Deep copy, twice. Copy constructor and operator=: original and copy independent (p. 11). operator= handles self-assignment and frees the old content.
  • ✓
    operator[] in two versions (const and non-const), with a bounds check and std::exception (p. 11). A negative index becomes a large unsigned int: out of bounds too.
  • ✓
    size() is const, with no parameter (p. 11).
  • ✓
    Hygiene. c++ -Wall -Wextra -Werror -std=c++98, canonical form, include guards, no using namespace, no STL, no leak. A small modification may be requested at the defense (p. 12).
