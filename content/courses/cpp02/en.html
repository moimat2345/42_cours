01

The module at a glance

You write a Fixed class that represents a fixed-point number: a number with a fractional part stored in a plain int, whose last 8 bits hold the fractional part. The module builds in layers, with the same class carried from one exercise to the next: ex00 lays it down, ex01 makes it useful, ex02 teaches it to compute, and ex03 (optional) uses it to tell whether a point is inside a triangle.

Two ideas carry the whole module. The Orthodox Canonical Form: from here on, every class defines its own four basic functions (default constructor, copy constructor, copy assignment operator, destructor). And operator overloading: making a + b, a < b or std::cout << a work with your own class.

The Orthodox Canonical Form

From this module on, all your classes are in Orthodox Canonical Form, unless the subject says otherwise (p. 6). It comes down to four member functions that you write yourself:

FunctionDeclaration for FixedCalled when
Default constructorFixed( void );Fixed a;
Copy constructorFixed( Fixed const & src );Fixed b( a ); and Fixed c = a;, but also passing or returning by value
Copy assignment operatorFixed & operator=( Fixed const & rhs );c = b; (c already exists)
Destructor~Fixed( void );At the end of the object's scope

Why write them by hand? If you don't, the compiler generates them for you. Writing them gives you control over what happens, which becomes essential as soon as a class owns memory. Here, you mostly write them to see when each one is called: the subject shows an output where each function prints a message (p. 10).

who gets called?
Fixed a;         // default constructor
Fixed b( a );    // copy constructor: b does not exist yet
Fixed c;         // default constructor
c = b;            // copy assignment operator: c already exists
Fixed d = a;     // copy constructor, despite the = sign
                  // then one destructor per object at the end of the scope, in reverse order
⚠️

Copy or assignment? The = sign doesn't decide: if the object is created on that line, it's a constructor; if it already existed, it's the assignment operator. Count your messages: every object constructed (by default, by copy, from an int...) must end with exactly one Destructor called.

Two details about the assignment operator. It returns *this by reference, which allows chaining a = b = c;. And a this != &rhs test avoids copying an object onto itself: harmless for an int, but essential the day the class manages memory.

Many implementations make the copy constructor call the assignment operator. That's why the subject notes, on its sample output, that the "Copy assignment operator called" line may be missing depending on your implementation (p. 10). Initializing the member directly in the copy constructor is another valid choice: both can be defended, so be ready to explain yours.

04

Operator overloading

In C++, a + b is just another way to write a function call: a.operator+( b ). Overloading an operator means writing that function for your class. The same symbol then does different things depending on the type of its operands: that's the ad-hoc polymorphism in the module's title.

An operator comes in two forms. Member: the left operand is the object itself (*this) and the function receives the right operand. Free (outside the class): the function receives both operands. You need a free function when the left operand isn't of your class, as in std::cout << a.

Fixed   operator++( int );                    // a++  (the int only tells them apart)

⚠️

Why << has to be free. Written as a method of Fixed, it would have a as its left operand: you would write a << std::cout, and std::cout << a would no longer compile (observed with clang). You can't add a method to std::ostream. And since friend is forbidden (p. 4), the free function goes through the class's public interface, for example toFloat().

A tip to write less code: define == and < for real, then express the four other comparisons from them (!= is the opposite of ==...). It's up to you to find which ones follow from which.

ex00 · Fixed

What you're asked. A first class in canonical form that represents a fixed-point number and, for now, only knows how to store its raw integer. The point of the exercise is the canonical form, not the conversion.

The idea of a fixed-point number. An int can store integers. To fit a number with a fractional part into it, you decide that its last 8 bits are "after the point". The stored integer (the raw value) is then value × 28, that is value × 256. The subject asks you to read a three-page article on integers and floating-point numbers before you start (p. 9).

What the subject requires (p. 10). Private members: an integer that stores the value, and a static constant integer that stores the number of fractional bits, always equal to the integer literal 8. Public members: the default constructor (value initialized to 0), the copy constructor, the copy assignment operator, the destructor, int getRawBits( void ) const; and void setRawBits( int const raw );.

Files to submit (p. 9). Makefile, main.cpp, Fixed.hpp (or Fixed.h) and Fixed.cpp. No function is forbidden.

Where do you give the value 8? Either in the class (static int const _fractionalBits = 8;) or in the .cpp (int const Fixed::_fractionalBits = 8;). With the first form, if you pass the constant to a function that takes an int const &, the linker may complain about an undefined symbol (observed with clang without optimization; optimization can hide it). Defining it in the .cpp avoids that trap. Also remember to mark getRawBits as const: without it you can't call it on a Fixed const, and the next exercise creates some.

ex01 · Conversions

What you're asked (p. 11). The ex00 class can only represent 0. Add:

  • a constructor that takes a constant int and converts it to the corresponding fixed-point value;
  • a constructor that takes a constant float and converts it to the corresponding fixed-point value;
  • float toFloat( void ) const; and int toInt( void ) const;;
  • in the class files, an overload of the insertion operator << that writes the floating-point representation of the number into the output stream passed as a parameter.

Both constructors keep 8 fractional bits, as in ex00. Files to submit: the same as ex00. Authorized: roundf from <cmath> (p. 11).

The reasoning. Everything follows from the ex00 formula: raw = value × 256.

FunctionDirectionThe idea
Fixed( int const )int → rawMultiply by 256, that is shift 8 bits to the left.
Fixed( float const )float → rawMultiply by 256 then round with roundf.
toFloat()raw → floatDivide the raw value by 256, in floating point.
toInt()raw → intShift by 8 bits (raw >> 8), i.e. divide by 256 rounding down: the fractional part disappears.

Why roundf and not a plain truncation? Because 42.42f × 256 doesn't come out even: it gives about 10859.52. Truncating would give 10859, that is 42.418; rounding gives 10860, that is 42.4219, the value the subject shows. Write 1 << _fractionalBits rather than hard-coding 256: the constant stays the single source of truth.

Play with the demo. Type 42.42f in float mode: the raw value is 10860. Type 10 in int mode: it's 2560. Then move the slider to see the precision change, and try an integer that is too big.

Demo: you type an int or a float and see what Fixed stores with 8 fractional bits. 42.42f gives the raw value 10860: toFloat() returns 42.421875, toInt() returns 42 and std::cout prints 42.4219. 10 gives 2560. A slider changes the number of fractional bits to show how the precision changes.

The header gains these declarations. The free << function is declared after the class, and the header includes <iostream> for std::ostream: a header must stand on its own (p. 4).

ex02 · Operators

What you're asked (p. 13). Add to the class, as public member functions:

  • the 6 comparison operators: >, <, >=, <=, ==, !=;
  • the 4 arithmetic operators: +, -, *, /;
  • the 4 increment/decrement operators (pre and post), which increase or decrease the value by the smallest representable ε, such that 1 + ε > 1;
  • four public static member functions: two min and two max, one taking references to Fixed, the other references to constant Fixed, returning a reference to the smallest or the greatest.

Files to submit: the same as ex00. Authorized: roundf (p. 13).

ex02/Fixed.hpp (additions)
class Fixed
{

        // ... ex00 and ex01, plus:
        bool    operator>( Fixed const & rhs ) const;
        bool    operator<( Fixed const & rhs ) const;
        bool    operator>=( Fixed const & rhs ) const;

        Fixed & operator++( void );        // ++a: returns the modified object
        Fixed   operator++( int );         // a++: returns the old value
        Fixed & operator--( void );
        Fixed   operator--( int );

        static Fixed &         min( Fixed & a, Fixed & b );
        static Fixed const &   min( Fixed const & a, Fixed const & b );
        static Fixed &         max( Fixed & a, Fixed & b );
        static Fixed const &   max( Fixed const & a, Fixed const & b );
};

Comparisons. Compare the raw values, which are integers: the result is exact. Going through toFloat() to compare would only bring rounding back in.

Addition and subtraction. Both raw values have the same scale (× 256): adding or subtracting the raw values gives the raw value of the result.

Multiplication and division. Here the scale matters. The product of two raw values is at scale 256 × 256, that is 216: it has to be brought back to scale 256 (a shift of 8 bits). That product can also overflow an int (1000 × 1000 already gives raw values of 256000 and a product of over 6 × 1010), so ask yourself what the intermediate type should be. The long long type is not strict C++98 (clang rejects it with -pedantic -Werror, observed) and the size of long depends on the machine: check on your school's. For division, it's the opposite: the quotient of two raw values has no scale left, so put it back before dividing, otherwise you lose the whole fractional part. Another route exists: go through float values and rebuild a Fixed with the ex01 constructor. Each choice has its limits in precision and range, and you must be able to state them.

Increment and decrement. The smallest representable step is a raw value of 1, that is ε = 1 / 256 = 0.00390625. That's exactly what the subject's output shows: after a ++a on a Fixed at 0, you read 0.00390625. The prefix form modifies then returns the object (by reference). The postfix form must return the value from before: it keeps a copy, increments, then returns that copy, by value.

min and max. You return one of the two objects you received, not a copy, hence the references. Two versions of each so that it works with const objects as well as modifiable ones (see the pitfalls).

The expected result. The subject gives this main (p. 14): a Fixed a, a Fixed const b( Fixed( 5.05f ) * Fixed( 2 ) ), then a, ++a, a, a++, a, b and Fixed::max( a, b ). Without the constructor and destructor messages, as in the subject's example:

ex03 · BSP

What you're asked (p. 15-16). Reuse your Fixed class to write a function that tells whether a point is inside a triangle. BSP stands for Binary Space Partitioning. This exercise is optional: you can pass the module without it (p. 15).

Files to submit (p. 15). Makefile, main.cpp, Fixed.hpp (or .h), Fixed.cpp, Point.hpp (or .h), Point.cpp and bsp.cpp. Authorized: roundf.

What the subject requires (p. 16). A Point class in canonical form that represents a 2D point: two private attributes Fixed const x and Fixed const y (and "anything else useful"), a default constructor that sets x and y to 0, a constructor that takes two constant float values, the copy constructor, the assignment operator and the destructor. Then the function bool bsp( Point const a, Point const b, Point const c, Point const point );: a, b, c are the vertices, point is the point to test. It returns true if the point is inside the triangle, false otherwise, and false too if the point is a vertex or is on an edge. The subject asks you to write and turn in your own tests.

        Fixed const      _x;

#endif

The subject doesn't list a bsp.hpp: declaring bsp in Point.hpp and implementing it in bsp.cpp is one possible choice (advice, not a rule of the subject).

The geometric idea. For each edge of the triangle, ask which side of the edge the point is on. The answer is the sign of a cross product: for the edge from a to b, it's (b.x − a.x) × (p.y − a.y) − (b.y − a.y) × (p.x − a.x), which is twice the signed area of the triangle a b p. The point is strictly inside when the three products (edges ab, bc, ca) are non-zero and have the same sign. A zero product means the point is on the line of the edge: on the edge or on a vertex, so false according to the subject, or on its extension, so outside anyway. You can also compare the area of the big triangle with the sum of the three small ones: same result, but then remember to rule out the zero areas separately.

Place the point in the demo: click on the drawing, or type its coordinates. Try the five example buttons, then look for a point outside where a product still cancels out (on the extension of an edge).

Demo: the triangle a(0,0), b(10,0), c(5,10) and a point you place. bsp() computes three cross products, one per edge: (5,5) gives true (all three are positive). (5,0) (on an edge), (0,0) (a vertex) and (20,20) (outside) give false.

The expected result. The subject shows no output for this exercise: it asks for your own tests (p. 16). With the triangle a(0,0), b(10,0), c(5,10), your function should answer:

The coordinates go through Fixed, so through 8 fractional bits: a point within half a step (1/512) of a line is rounded onto it. Observed with a test implementation compiled with clang (C++98): Point( 5, 0.001f ) gives false (y becomes 0) and Point( 5, 0.002f ) gives true (y becomes 0.00390625).

⚠️

const attributes and an operator=. The subject wants Fixed const members in Point and an assignment operator (p. 16). But you can't modify a const member: an operator= that writes _x = rhs._x; doesn't compile, and without an operator= the compiler refuses to generate its own as soon as you write a = b (observed with clang). You have to decide what your operator should do, and be able to justify it at the defense. That's the point the subject makes you discover.

💡

Copies make noise. bsp takes its four Point arguments by value (p. 16): each call builds copies. If your constructors print a message, your output will be long. Keep the messages for the exercises that ask for them, or turn them off for this one: it's your choice, the subject sets no output for ex03.

10

Classic pitfalls

⚠️

operator<< as a method. It has to be a free function: inside the class, std::cout << a doesn't compile (see the overloading section). Declare it after the class, in the same header, and have it return the stream it received.

⚠️

Prefix versus postfix. The postfix is recognized by its dummy int parameter, which you leave unnamed: named and unused, it triggers -Wunused-parameter, hence an error with -Werror (observed). The postfix returns a copy of the old value: returning a reference to that local copy doesn't compile with -Werror ("reference to stack memory", observed with clang) and would be a bug anyway. Conversely, if the prefix returns a copy instead of a reference, ++(++a) increments only once: the second increment acts on the copy (observed).

⚠️

Division by zero. The subject accepts that the program crashes (p. 14). What really happens depends on your computation and your machine. Observed with clang on macOS: an integer division by zero doesn't crash on arm64 (the observed result is 0) but crashes on x86_64 (emulated with Rosetta; signal SIGFPE, exit code 136); a float division gives infinity, which the conversion to int turns into INT_MAX on arm64 and INT_MIN on x86_64. Choose what your operator does, and be able to say it; also check on your school's machine.

⚠️

Overflow. The raw value is an int: with 8 fractional bits, the int constructor only handles −8388608 to 8388607 correctly. Beyond that, the result is wrong and, for a left shift that leaves the range of a signed int, the behavior is undefined in C++98: with clang, 8388608 << 8 gave −2147483648 and −8388609 << 8 gave a positive number; the ex01 demo shows it. A float that is too big causes the same problem at the conversion to int, whose result depends on the processor. And the product of two raw values in the multiplication overflows much sooner: 256000 × 256000 doesn't fit in an int.

⚠️

min and max with const objects. With a Fixed const b, only the version taking constant references can apply, and it returns a constant reference. Writing Fixed & r = Fixed::max( a, b ); with a constant b doesn't compile ("drops const qualifier", observed). With two modifiable Fixed objects, the first version is chosen and you can keep a modifiable reference. If you only write the non-const version, a constant object is rejected; if you only write the const version, you can no longer get a modifiable reference back.

⚠️

Comparing floating-point numbers. Don't compare two toFloat() results with ==: compare the raw values, which are integers. And don't expect arithmetic identities from a number that isn't representable: 0.1 doesn't exist exactly in fixed point (its raw value is 26, that is 0.1015625). Fixed( 0.1f ) * Fixed( 10 ) gives the raw value 260, not 256: the result is 1.015625 and is not equal to Fixed( 1 ) (observed). The same rounding explains why Fixed( 42.42f ).toFloat() doesn't return 42.42.

⚠️

A double instead of a float. Fixed a( 5.05 ); is ambiguous: a double converts equally well to int and to float, and the compiler refuses ("call to constructor is ambiguous", observed). That's why the subject writes 5.05f. Write the f suffix in your tests.

⚠️

toInt() and negative numbers. For a negative raw value, shifting (raw >> 8) rounds down: −1.5 gives −2, whereas raw / 256 and the ( int ) cast of a float round toward zero and give −1 (observed with clang). The subject doesn't specify this case (p. 11). Choose, test, and be ready to justify it.

⚠️

The rules worth 0 or −42. Code in a header (except templates), forgotten include guards, a header that doesn't compile on its own: 0 (p. 4). using namespace, friend, a container or <algorithm>: −42 (p. 4). printf, malloc, free: 0 (p. 3).

💡

Good practice: once the messages print, reread your output. A number of Destructor called different from the number of constructions points to a forgotten object or a copy you didn't expect, for example a pass by value that should be a constant reference.

11

How I did it

I kept a single Fixed class, copied from one exercise to the next and then extended. Each canonical-form function prints its message, and the copy constructor relies on the assignment operator. The int constructor shifts the number by 8 bits; the float constructor multiplies by 256 then rounds with roundf; toFloat() and toInt() go the other way. For arithmetic, I go through floats and rebuild a Fixed with the float constructor. The comparisons and the four min / max work on the raw values, and ++ and -- add or subtract 1 to the raw value. My main functions reuse the subject's. I haven't written exercise 03 yet: the directory exists, but Point and bsp are still to do.
