01

Le module en bref

Tu écris une classe Fixed qui représente un nombre à virgule fixe : un nombre à virgule rangé dans un simple int, dont les 8 derniers bits portent la partie fractionnaire. Le module avance par couches, avec la même classe d'un exercice au suivant : ex00 la pose, ex01 la rend utile, ex02 lui apprend à calculer, et ex03 (facultatif) s'en sert pour dire si un point est dans un triangle.

Deux idées portent tout le module. La forme canonique orthodoxe : à partir d'ici, chaque classe définit elle-même ses quatre fonctions de base (constructeur par défaut, constructeur de copie, opérateur d'affectation, destructeur). Et la surcharge d'opérateurs : faire fonctionner a + b, a < b ou std::cout << a avec ta propre classe.

03

La forme canonique orthodoxe

À partir de ce module, toutes tes classes sont en forme canonique orthodoxe, sauf mention contraire du sujet (p. 6). Elle tient en quatre fonctions membres que tu écris toi-même :

FonctionDéclaration pour FixedAppelée quand
Constructeur par défautFixed( void );Fixed a;
Constructeur de copieFixed( Fixed const & src );Fixed b( a ); et Fixed c = a;, mais aussi un passage ou un retour par valeur
Opérateur d'affectationFixed & operator=( Fixed const & rhs );c = b; (c existe déjà)
Destructeur~Fixed( void );À la fin de la portée de l'objet

Pourquoi les écrire à la main ? Si tu ne le fais pas, le compilateur les génère pour toi. Les écrire te donne le contrôle de ce qui se passe, ce qui deviendra indispensable dès qu'une classe possédera de la mémoire. Ici, tu les écris surtout pour voir quand chacune est appelée : le sujet montre une sortie où chaque fonction affiche un message (p. 10).

qui est appelé ?
Fixed a;         // constructeur par défaut
Fixed b( a );    // constructeur de copie : b n'existe pas encore
Fixed c;         // constructeur par défaut
c = b;            // opérateur d'affectation : c existe déjà
Fixed d = a;     // constructeur de copie, malgré le signe =
                  // puis un destructeur par objet à la fin de la portée, dans l'ordre inverse
⚠️

Copie ou affectation ? Le signe = ne décide pas : si l'objet est créé sur cette ligne, c'est un constructeur ; s'il existait déjà, c'est l'opérateur d'affectation. Compte tes messages : chaque objet construit (par défaut, par copie, depuis un int…) doit finir par exactement un Destructor called.

Deux détails de l'opérateur d'affectation. Il renvoie *this par référence, pour permettre le chaînage a = b = c;. Et un test this != &rhs évite de se copier sur soi-même : sans conséquence pour un int, mais indispensable le jour où la classe gère de la mémoire.

Beaucoup d'implémentations font appeler l'opérateur d'affectation par le constructeur de copie. C'est pour cela que le sujet précise, sur sa sortie d'exemple, que la ligne « Copy assignment operator called » peut manquer selon ton implémentation (p. 10). Initialiser directement le membre dans le constructeur de copie est un autre choix valable : les deux se défendent, sois prêt à expliquer le tien.

04

La surcharge d'opérateurs

En C++, a + b n'est qu'une autre façon d'écrire un appel de fonction : a.operator+( b ). Surcharger un opérateur, c'est écrire cette fonction pour ta classe. Le même symbole fait alors des choses différentes selon le type de ses opérandes : c'est le polymorphisme ad-hoc du titre du module.

Un opérateur s'écrit sous deux formes. Membre : l'opérande de gauche est l'objet lui-même (*this) et la fonction reçoit l'opérande de droite. Libre (hors de la classe) : la fonction reçoit les deux opérandes. Il faut une fonction libre quand l'opérande de gauche n'est pas de ta classe, comme dans std::cout << a.

OpérateursFormeCe qu'ils renvoient
== != < > <= >=membre, constun bool
+ - * /membre, constun nouveau Fixed, par valeur : les opérandes ne changent pas
++a --a (préfixe)membreFixed & : l'objet modifié lui-même
a++ a-- (postfixe)membre, avec un paramètre int facticeun Fixed par valeur : l'ancienne valeur
=membreFixed & (*this)
<<librestd::ostream &, pour enchaîner les <<
Fixed.hpp (extrait)
Fixed   operator+( Fixed const & rhs ) const;   // a + b  ==  a.operator+( b )
bool    operator<( Fixed const & rhs ) const;
Fixed & operator++( void );                   // ++a
Fixed   operator++( int );                    // a++  (le int ne sert qu'à distinguer)

// hors de la classe :
std::ostream & operator<<( std::ostream & out, Fixed const & value );
⚠️

Pourquoi << doit être libre. Écrit comme une méthode de Fixed, il aurait a comme opérande de gauche : on écrirait a << std::cout, et std::cout << a ne compilerait plus (constaté avec clang). Tu ne peux pas ajouter de méthode à std::ostream. Et comme friend est interdit (p. 4), la fonction libre passe par l'interface publique de la classe, par exemple toFloat().

Un conseil pour écrire moins de code : définis == et < en vrai, puis exprime les quatre autres comparaisons à partir d'eux (!= est le contraire de ==…). À toi de trouver lesquelles découlent de lesquelles.

ex00 · Fixed

Ce qu'on te demande. Une première classe en forme canonique qui représente un nombre à virgule fixe, et qui ne sait encore stocker que son entier brut. Le but de l'exercice est la forme canonique, pas la conversion.

L'idée d'un nombre à virgule fixe. Un int sait stocker des entiers. Pour y ranger un nombre à virgule, on décide que ses 8 derniers bits sont « après la virgule ». L'entier stocké (le raw) vaut alors valeur × 28, c'est-à-dire valeur × 256. Le sujet te demande de lire un article en trois pages sur les entiers et les nombres flottants avant de commencer (p. 9).

Ce que le sujet impose (p. 10). Membres privés : un entier qui stocke la valeur, et une constante entière statique qui stocke le nombre de bits fractionnaires, toujours égale au littéral entier 8. Membres publics : le constructeur par défaut (valeur initialisée à 0), le constructeur de copie, l'opérateur d'affectation, le destructeur, int getRawBits( void ) const; et void setRawBits( int const raw );.

Fichiers à rendre (p. 9). Makefile, main.cpp, Fixed.hpp (ou Fixed.h) et Fixed.cpp. Aucune fonction n'est interdite.

La définition dans le .cpp évite ce piège. Pense aussi à marquer getRawBits avec const : sans cela, impossible de l'appeler sur un Fixed const, et l'exercice suivant en crée.

ex01 · Conversions

Ce qu'on te demande (p. 11). La classe d'ex00 ne sait représenter que 0. Ajoute :

  • un constructeur qui prend un int constant et le convertit en valeur fixe ;
  • un constructeur qui prend un float constant et le convertit en valeur fixe ;
  • float toFloat( void ) const; et int toInt( void ) const; ;
  • dans les fichiers de la classe, une surcharge de l'opérateur d'insertion << qui écrit la représentation flottante du nombre dans le flux reçu en paramètre.

Les deux constructeurs gardent 8 bits fractionnaires, comme en ex00. Fichiers à rendre : les mêmes qu'en ex00. Autorisé : roundf de <cmath> (p. 11).

Le raisonnement. Tout découle de la formule d'ex00 : raw = valeur × 256.

FonctionSensL'idée
Fixed( int const )int → rawMultiplier par 256, c'est-à-dire décaler de 8 bits vers la gauche.
Fixed( float const )float → rawMultiplier par 256 puis arrondir avec roundf.
toFloat()raw → floatDiviser le raw par 256, en flottant.
toInt()raw → intDécaler de 8 bits (raw >> 8), soit diviser par 256 en arrondissant vers le bas : la partie fractionnaire disparaît.

Pourquoi roundf et pas une simple troncature ? Parce que 42.42f × 256 ne tombe pas juste : cela donne environ 10859.52. Tronquer donnerait 10859, soit 42.418 ; arrondir donne 10860, soit 42.4219, la valeur que montre le sujet. Écris plutôt 1 << _fractionalBits que le nombre 256 en dur : la constante reste la seule source de vérité.

Joue avec la démo. Saisis 42.42f en mode float : le raw vaut 10860. Saisis 10 en mode int : il vaut 2560. Puis bouge le curseur pour voir la précision changer, et tente un entier trop grand.

Démo : tu saisis un int ou un float et tu vois ce que Fixed stocke avec 8 bits fractionnaires. 42.42f donne la valeur brute 10860 : toFloat() renvoie 42.421875, toInt() renvoie 42 et std::cout affiche 42.4219. 10 donne 2560. Un curseur fait varier le nombre de bits fractionnaires pour montrer comment la précision change.

Le header gagne ces déclarations. La fonction libre << se déclare après la classe, et le header inclut <iostream> pour std::ostream : un header doit se suffire à lui-même (p. 4).

ex02 · Opérateurs

Ce qu'on te demande (p. 13). Ajoute à la classe, en fonctions membres publiques :

  • les 6 opérateurs de comparaison : >, <, >=, <=, ==, != ;
  • les 4 opérateurs arithmétiques : +, -, *, / ;
  • les 4 opérateurs d'incrémentation et de décrémentation (pré et post), qui augmentent ou diminuent la valeur du plus petit ε représentable, tel que 1 + ε > 1 ;
  • quatre fonctions membres publiques statiques : deux min et deux max, l'une avec des références sur des Fixed, l'autre avec des références sur des Fixed constants, qui renvoient une référence sur le plus petit ou le plus grand.

Fichiers à rendre : les mêmes qu'en ex00. Autorisé : roundf (p. 13).

Comparaisons. Compare les raw, des entiers : le résultat est exact. Passer par toFloat() pour comparer ne ferait que réintroduire des arrondis.

Addition et soustraction. Les deux raw ont la même échelle (× 256) : additionner ou soustraire les raw donne le raw du résultat.

Multiplication et division. Ici l'échelle compte. Le produit de deux raw est à l'échelle 256 × 256, soit 216 : il faut le ramener à l'échelle 256 (un décalage de 8 bits). Ce produit peut aussi sortir d'un int (1000 × 1000 donne déjà des raw de 256000 et un produit de plus de 6 × 1010), donc pose-toi la question du type intermédiaire. Le type long long n'est pas du C++98 strict (clang le refuse avec -pedantic -Werror, constaté) et la taille de long dépend de la machine : à vérifier sur celle de ton école. Pour la division, c'est le contraire : le quotient de deux raw n'a plus d'échelle, donc remets-la avant de diviser, sans quoi tu perds toute la partie fractionnaire. Une autre voie existe : passer par des float et reconstruire un Fixed avec le constructeur de l'ex01. Chaque choix a ses limites de précision et de plage, et tu dois pouvoir les dire.

Incrémentation et décrémentation. Le plus petit pas représentable est un raw de 1, soit ε = 1 / 256 = 0.00390625. C'est exactement ce que montre la sortie du sujet : après un ++a sur un Fixed à 0, on lit 0.00390625. La forme préfixe modifie puis renvoie l'objet (par référence). La forme postfixe doit renvoyer la valeur d'avant : elle en garde une copie, incrémente, puis renvoie cette copie, par valeur.

min et max. On renvoie l'un des deux objets reçus, pas une copie, d'où les références. Deux versions de chaque pour que cela marche aussi bien avec des objets const qu'avec des objets modifiables (voir les pièges).

Le résultat attendu. Le sujet donne ce main (p. 14) : un Fixed a, un Fixed const b( Fixed( 5.05f ) * Fixed( 2 ) ), puis a, ++a, a, a++, a, b et Fixed::max( a, b ). Sans les messages des constructeurs et destructeurs, comme dans l'exemple du sujet :

sortie attendue, p. 14

Lis-la : ++a affiche la valeur déjà incrémentée, a++ affiche l'ancienne (encore 0.00390625) et laisse a à 0.0078125. Et b vaut 5.05f × 2 : 5.05f devient le raw 1293, soit 5.05078125, doublé en 10.1015625, que cout arrondit à 10.1016.

ex03 · BSP

Ce qu'on te demande (p. 15-16). Réutiliser ta classe Fixed pour écrire une fonction qui dit si un point est dans un triangle. BSP veut dire Binary Space Partitioning. Cet exercice est facultatif : on peut valider le module sans lui (p. 15).

Fichiers à rendre (p. 15). Makefile, main.cpp, Fixed.hpp (ou .h), Fixed.cpp, Point.hpp (ou .h), Point.cpp et bsp.cpp. Autorisé : roundf.

Ce que le sujet impose (p. 16). Une classe Point en forme canonique, qui représente un point 2D : deux attributs privés Fixed const x et Fixed const y (et « tout ce qui est utile »), un constructeur par défaut qui met x et y à 0, un constructeur qui prend deux float constants, le constructeur de copie, l'opérateur d'affectation et le destructeur. Puis la fonction bool bsp( Point const a, Point const b, Point const c, Point const point ); : a, b, c sont les sommets, point le point testé. Elle renvoie true si le point est dans le triangle, false sinon, et false aussi si le point est un sommet ou est sur une arête. Le sujet demande que tu écrives et rendes tes propres tests.

Le sujet ne liste pas de bsp.hpp : déclarer bsp dans Point.hpp et l'implémenter dans bsp.cpp est un choix possible (un conseil, pas une règle du sujet).

L'idée géométrique. Pour chaque arête du triangle, demande de quel côté de l'arête se trouve le point. La réponse est le signe d'un produit vectoriel : pour l'arête de a à b, c'est (b.x − a.x) × (p.y − a.y) − (b.y − a.y) × (p.x − a.x), soit le double de l'aire signée du triangle a b p. Le point est strictement dedans quand les trois produits (arêtes ab, bc, ca) sont non nuls et de même signe. Un produit nul veut dire que le point est sur la droite de l'arête : sur l'arête ou sur un sommet, donc false d'après le sujet, ou sur son prolongement, donc dehors de toute façon. Tu peux aussi comparer l'aire du grand triangle à la somme des trois petites : même résultat, mais n'oublie pas alors d'écarter à part les aires nulles.

Place le point dans la démo : clique sur le dessin, ou saisis ses coordonnées. Essaie les cinq boutons d'exemple, puis cherche un point dehors dont un produit s'annule quand même (sur le prolongement d'une arête).

Démo : le triangle a(0,0), b(10,0), c(5,10) et un point que tu places. bsp() calcule trois produits vectoriels, un par arête : (5,5) donne true (les trois sont positifs). (5,0) (sur une arête), (0,0) (un sommet) et (20,20) (dehors) donnent false.

Le résultat attendu. Le sujet ne montre pas de sortie pour cet exercice : il te demande tes propres tests (p. 16). Avec le triangle a(0,0), b(10,0), c(5,10), ta fonction doit répondre :

(5, 0)falsesur l'arête ab

Les coordonnées passent par Fixed, donc par 8 bits fractionnaires : un point à moins d'un demi-pas (1/512) d'une arête est arrondi sur elle. Constaté avec une implémentation de test compilée avec clang (C++98) : Point( 5, 0.001f ) donne false (le y devient 0) et Point( 5, 0.002f ) donne true (le y devient 0.00390625).

⚠️

Des attributs const et un operator=. Le sujet veut des Fixed const dans Point et un opérateur d'affectation (p. 16). Or on ne peut pas modifier un membre const : un operator= qui écrit _x = rhs._x; ne compile pas, et sans operator= le compilateur refuse de générer le sien dès que tu écris a = b (constaté avec clang). Il te reste à décider ce que ton opérateur doit faire, et à pouvoir le justifier en soutenance. C'est le point que le sujet te fait découvrir.

💡

Les copies font du bruit. bsp prend ses quatre Point par valeur (p. 16) : chaque appel construit des copies. Si tes constructeurs affichent un message, ta sortie sera longue. Garde les messages pour les exercices qui les demandent, ou coupe-les pour cet exercice : c'est ton choix, le sujet ne fixe pas de sortie pour ex03.

Pièges classiques

⚠️

operator<< en méthode. Il doit être une fonction libre : dans la classe, std::cout << a ne compile pas (voir la section sur la surcharge). Déclare-le après la classe, dans le même header, et fais-le renvoyer le flux reçu.

⚠️

Préfixe contre postfixe. Le postfixe se reconnaît à son paramètre int factice, que tu ne nommes pas : nommé et inutilisé, il déclenche -Wunused-parameter, donc une erreur avec -Werror (constaté). Le postfixe renvoie une copie de l'ancienne valeur : renvoyer une référence sur cette copie locale ne compile pas avec -Werror (« reference to stack memory », constaté avec clang) et serait un bug de toute façon. À l'inverse, si le préfixe renvoie une copie au lieu d'une référence, ++(++a) n'incrémente qu'une fois : la seconde incrémentation agit sur la copie (constaté).

⚠️

La division par zéro. Le sujet accepte que le programme plante (p. 14). Ce qui se passe réellement dépend de ton calcul et de ta machine. Constaté avec clang sur macOS : une division entière par zéro ne plante pas sur arm64 (le résultat observé est 0) mais plante sur x86_64 (émulé avec Rosetta ; signal SIGFPE, code de sortie 136) ; une division en float donne l'infini, que la conversion en int change en INT_MAX sur arm64 et en INT_MIN sur x86_64. Choisis ce que ton opérateur fait, et sache le dire ; vérifie aussi sur la machine de ton école.

⚠️

Le débordement. Le raw est un int : avec 8 bits fractionnaires, le constructeur int ne gère correctement que de −8388608 à 8388607. Au-delà, le résultat est faux et, pour un décalage à gauche qui sort de la plage d'un int signé, le comportement n'est pas défini en C++98 : avec clang, 8388608 << 8 a donné −2147483648 et −8388609 << 8 un nombre positif ; la démo de l'ex01 le montre. Un float trop grand pose le même problème à la conversion en int, dont le résultat dépend du processeur. Et le produit de deux raw dans la multiplication déborde bien plus tôt : 256000 × 256000 ne tient pas dans un int.

⚠️

min et max et les objets const. Avec un Fixed const b, seule la version à références constantes peut s'appliquer, et elle renvoie une référence constante. Écrire Fixed & r = Fixed::max( a, b ); avec un b constant ne compile pas (« drops const qualifier », constaté). Avec deux Fixed modifiables, la première version est choisie et tu peux garder une référence modifiable. Si tu n'écris que la version non constante, un objet constant est refusé ; si tu n'écris que la version constante, tu ne peux plus récupérer une référence modifiable.

⚠️

Comparer des flottants. Ne compare pas deux toFloat() avec == : compare les raw, des entiers. Et n'attends pas d'identité arithmétique d'un nombre qui n'est pas représentable : 0.1 n'existe pas exactement en virgule fixe (son raw est 26, soit 0.1015625). Fixed( 0.1f ) * Fixed( 10 ) donne le raw 260, pas 256 : le résultat est 1.015625 et ne vaut pas Fixed( 1 ) (constaté). Le même arrondi explique que Fixed( 42.42f ).toFloat() ne rende pas 42.42.

⚠️

Un double à la place d'un float. Fixed a( 5.05 ); est ambigu : un double se convertit aussi bien en int qu'en float, et le compilateur refuse (« call to constructor is ambiguous », constaté). C'est pour cela que le sujet écrit 5.05f. Écris le suffixe f dans tes tests.

⚠️

toInt() et les négatifs. Pour un raw négatif, décaler (raw >> 8) arrondit vers le bas : −1.5 donne −2, alors que raw / 256 et le cast ( int ) d'un float arrondissent vers zéro et donnent −1 (constaté avec clang). Le sujet ne précise pas ce cas (p. 11). Choisis, teste, et sois prêt à justifier.

⚠️

Les règles qui valent 0 ou −42. Du code dans un header (hors templates), des gardes d'inclusion oubliées, un header qui ne compile pas seul : 0 (p. 4). using namespace, friend, un conteneur ou <algorithm> : −42 (p. 4). printf, malloc, free : 0 (p. 3).

💡

Bonne pratique : une fois les messages affichés, relis ta sortie. Un nombre de Destructor called différent du nombre de constructions signale un objet oublié ou une copie que tu n'attendais pas, par exemple un passage par valeur qui devrait être une référence constante.

Comment je l'ai fait

J'ai gardé une seule classe Fixed, copiée d'un exercice au suivant puis enrichie. Chaque fonction de la forme canonique affiche son message, et le constructeur de copie s'appuie sur l'opérateur d'affectation. Le constructeur int décale le nombre de 8 bits ; le constructeur float multiplie par 256 puis arrondit avec roundf ; toFloat() et toInt() font le chemin inverse. Pour l'arithmétique, je repasse par les flottants et je reconstruis un Fixed avec le constructeur float. Les comparaisons et les quatre min / max travaillent sur les raw, et ++ et -- ajoutent ou retirent 1 au raw. Mes main reprennent ceux du sujet. Je n'ai pas encore écrit l'exercice 03 : le dossier existe, mais Point et bsp restent à faire.
