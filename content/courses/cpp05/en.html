The 2 things to understand before codingexceptions · the "upside down" grade

1 · What's an exception ?

In C, when something fails, you return -1 and the caller has to check. In C++, you can throw (throw) an error: the function stops dead, and the error bubbles up the call stack until the first catch that knows how to handle it. All the code in between is skipped.

① try
try { ... }

"I'm trying this block. If there's an exception in it, I want to catch it."

② throw
throw X;

Somewhere (even 5 functions down), an object gets thrown. Everything stops right here.

③ catch
catch (std::exception & e)

We land here. e.what() gives the error message.

the idea, in shortgeneric example
try
{
    Bureaucrat bob("Bob", 0);          // grade 0 = invalid → the constructor throws an exception
    std::cout << "never printed" << std::endl;   // skipped!
}
catch (std::exception & e)            // we catch ANY exception that inherits from std::exception
{
    std::cout << "Error: " << e.what() << std::endl;
}

Why does catch (std::exception & e) catch your own exception? Because your exception class is going to inherit from std::exception (it's the polymorphism from CPP04!). And you're going to override its virtual function what() so it returns your message.

The subject imposes names like Bureaucrat::GradeTooHighException: the :: means it's a class declared inside the Bureaucrat class (a nested class). Here's the template, you'll reuse it for every exception in the module:

nested exception template (in a .hpp)declaration
#include <exception>

class Bureaucrat
{
    public:
        // ... the rest of the class ...

        class GradeTooHighException : public std::exception
        {
            public:
                virtual const char* what() const throw();
        };
};
The weird bit: throw() In C++98, what() is declared in std::exception with throw() at the end, which means "this function never throws an exception." To override it, you must copy the exact same signature: virtual const char* what() const throw();. In the .cpp, you'll write const char* Bureaucrat::GradeTooHighException::what() const throw() { return "..."; }.
Classic trap We throw an object: throw GradeTooHighException(); (with parentheses → that constructs a temporary object). No new, no pointer. And we catch by reference: catch (std::exception & e).

2 · The grade is "upside down"

This is THE thing that confuses everyone. 1 = the highest grade (the boss), 150 = the lowest (the intern's intern). So:

▲ better worse ▼ 1 75 150

incrementGrade()

  • ↑The bureaucrat moves up in grade → the number decreases. 3 becomes 2.
  • ✗If the grade is already 1 → GradeTooHighException.

decrementGrade()

  • ↓The bureaucrat moves down → the number increases. 3 becomes 4.
  • ✗If the grade is already 150 → GradeTooLowException.

And for forms (ex01+): "having a high enough grade" = your number is smaller than or equal to the required number. A bureaucrat with grade 10 can sign a form that "requires grade 25". A grade 30 can't.

ex00

Bureaucrat« Mommy, when I grow up, I want to be a bureaucrat! »

What you need to do, in plain English: create a Bureaucrat class that has a name (which never changes) and a grade between 1 and 150. You can make its grade go up or down. As soon as something tries to set a grade outside [1, 150] — at construction or with increment/decrement — you throw an exception. And you can print it with std::cout << bureaucrat.

ex00/Bureaucrat.hppdeclarations
#ifndef BUREAUCRAT_HPP
#define BUREAUCRAT_HPP

#include <string>
#include <iostream>
#include <exception>

class Bureaucrat
{
    private:
        const std::string   _name;      // const → fixed at construction, never modified again
        int                 _grade;     // 1 (best) ... 150 (worst)

    public:
        // --- Canonical form ---
        Bureaucrat();                                   // default name/grade of your choice (valid!)
        Bureaucrat(const std::string & name, int grade); // may throw an exception
        Bureaucrat(const Bureaucrat & other);
        Bureaucrat & operator=(const Bureaucrat & other);
        ~Bureaucrat();

        // --- Getters (imposed names) ---
        const std::string & getName() const;
        int                 getGrade() const;

        // --- Changing grade ---
        void    incrementGrade();   // grade - 1  (may throw GradeTooHighException)
        void    decrementGrade();   // grade + 1  (may throw GradeTooLowException)

        // --- Exceptions (imposed names) ---
        class GradeTooHighException : public std::exception
        {
            public:
                virtual const char* what() const throw();
        };
        class GradeTooLowException : public std::exception
        {
            public:
                virtual const char* what() const throw();
        };
};

// Overload of << : FREE function (outside the class), not a method
std::ostream & operator<<(std::ostream & out, const Bureaucrat & b);

#endif

What each function must do

  • →Constructor (name, grade): if grade < 1 → throw TooHigh; if grade > 150 → throw TooLow; otherwise store it.
  • →increment / decrement: check before modifying, throw the same exception as the constructor.
  • →what(): just returns a string, e.g. "Grade too high".
  • →operator<<: writes to out and returns out (so you can chain the <<).

Traps

  • !Const name + operator=: impossible to reassign a const. In operator=, you only copy the grade. That's normal and expected.
  • !A const is initialized only in the initialization list: : _name(name), not in the constructor body.
  • !Moving up in grade = subtracting. Read that twice.

The expected result

The format of << is imposed (character for character, with the final period):

imposed format
<name>, bureaucrat grade <grade>.

The rest (error messages, tests) is up to you. Your main.cpp must prove that everything works. Example output from a good main:

./bureaucratexample
--- Test 1: valid bureaucrat ---
Bob, bureaucrat grade 2.
Bob, bureaucrat grade 1.       ← after incrementGrade()
Error: Grade too high          ← incrementGrade() called once too many
--- Test 2: invalid construction ---

Error: Grade too high          ← Bureaucrat("Tim", 0)
What your main should test (the grader will check) Valid creation · creation with 0 · creation with 151 · increment until it goes past 1 · decrement until it goes past 150 · printing with <<. Each dangerous case in its own try/catch, otherwise the first exception stops all the following tests.

What we add to Bureaucrat

ex01/Bureaucrat.hpp — the additionsdeclarations
class Form;          // above "class Bureaucrat", after the #include

class Bureaucrat
{
    // ... everything that was there in ex00 ...
    public:
        void    signForm(Form & form);   // NOT const: signing modifies the form
};
Why "class Bureaucrat;" all on its own? Form needs to know about Bureaucrat (for beSigned), and Bureaucrat needs to know about Form (for signForm). If each .hpp does #include of the other, it goes in circles and won't compile. Solution: in the .hpp, we just say "this class exists" (class Form;). That's enough to declare a reference Form &. The real #include "Form.hpp" goes in the .cpp, where you actually use its functions.

Who calls who?

Form::beSigned(bureaucrat)

  • 1Compares the bureaucrat's grade to the grade required to sign.
  • 2Good enough (grade <= required) → _signed = true.
  • 3Too low → throw Form::GradeTooLowException().
  • ·Doesn't print anything. It's the "engine".

Bureaucrat::signForm(form)

  • 1Calls form.beSigned(*this) inside a try.
  • 2It succeeds → prints <bureaucrat> signed <form>.
  • 3Exception caught → prints <bureaucrat> couldn't sign <form> because <reason>. (reason = e.what()).
  • ·It's the "interface" that prints.

The expected result

./formexample

Alice signed Permis                                              ← Alice grade 10
Bob couldn't sign Permis because Grade too low.                 ← Bob grade 120

What if we create a Form with an invalid grade? Same rules as Bureaucrat: Form("X", 0, 10) → Form::GradeTooHighException, Form("X", 10, 151) → Form::GradeTooLowException. Check both grades in the constructor.

ex02

AForm + the 3 forms« No, you need form 28B, not 28C... »

In plain English: you rename Form into AForm (A = Abstract) and make it abstract, exactly like Animal in CPP04 ex02: you can no longer do AForm f;. Then you create 3 concrete forms that inherit from AForm, each with a target (target, a string) and an action. Finally, a form can be executed by a bureaucrat, provided it's signed and the bureaucrat has the execution grade.

The 3 concrete forms

ClassSignExecuteAction when executed
ShrubberyCreationForm145137Creates a file <target>_shrubbery in the current directory and writes ASCII trees into it.
RobotomyRequestForm7245Prints drilling noises, then 1 time out of 2: "<target> has been robotomized successfully", otherwise "robotomy failed".
PresidentialPardonForm255Prints "<target> has been pardoned by Zaphod Beeblebrox".

Their constructor takes only one parameter: the target. The name and the grades, they provide themselves to AForm's constructor. E.g.: ShrubberyCreationForm("home") → creates home_shrubbery.

The class diagram

"One way is more elegant than the other"

The subject lets you choose where to check the conditions (signed? high enough grade?). Two options:

✗ Heavy option

  • ·Each concrete form overrides execute() and redoes the same checks.
  • ·3 times the same copy-pasted code. One slip-up = a bug.

✓ Elegant option

  • 1AForm::execute() (non-virtual) does the checks a single time and throws the exception if needed.
  • 2If everything's fine, it calls a pure virtual function (e.g. executeAction()) that each form implements with its own action.
  • ★Bonus: it's this = 0 function that makes AForm abstract.

The headers

ex02/AForm.hppdeclarations
#ifndef AFORM_HPP
#define AFORM_HPP

#include <string>
#include <iostream>
#include <exception>

class Bureaucrat;

class AForm
{
    private:                            // always PRIVATE, and they stay in the base class
        const std::string   _name;
        bool                _signed;
        const int           _gradeToSign;
        const int           _gradeToExecute;

    protected:
        // The action specific to each form. "= 0" → AForm becomes abstract.
        virtual void    executeAction() const = 0;

    public:
        AForm();
        AForm(const std::string & name, int gradeToSign, int gradeToExecute);
        AForm(const AForm & other);
        AForm & operator=(const AForm & other);
        virtual ~AForm();               // VIRTUAL: children will be destroyed through an AForm*

        const std::string & getName() const;
        bool                getSigned() const;
        int                 getGradeToSign() const;
        int                 getGradeToExecute() const;

        void    beSigned(const Bureaucrat & b);
        void    execute(Bureaucrat const & executor) const;   // imposed signature

        class GradeTooHighException : public std::exception
        { public: virtual const char* what() const throw(); };
        class GradeTooLowException : public std::exception
        { public: virtual const char* what() const throw(); };
        class FormNotSignedException : public std::exception      // new one!
        { public: virtual const char* what() const throw(); };
};

std::ostream & operator<<(std::ostream & out, const AForm & f);

#endif

ex02/Bureaucrat.hpp — changesdeclarations
class AForm;                                    // replaces "class Form;"

// inside the class:
        void    signForm(AForm & form);           // Form → AForm

AForm::execute(executor)

  • 1Not signed → throw FormNotSignedException()
  • 2Executor's grade > execution grade → throw GradeTooLowException()
  • 3Otherwise → executeAction() (polymorphism picks the right version).

Bureaucrat::executeForm(form)

  • 1Same idea as signForm: try { form.execute(*this); }
  • 2OK → <bureaucrat> executed <form>
  • 3Exception → an explicit error message (free choice), with e.what().
The C++ tools you'll need in the .cpp files Shrubbery: #include <fstream> then std::ofstream to create/write the file (in C++98, the constructor wants a const char* → (_target + "_shrubbery").c_str()). Think about the case where the file doesn't open.
Robotomy: std::rand() from <cstdlib>, an even or odd number = 50/50. Seed it only once with std::srand(std::time(0)) (<ctime>), e.g. at the start of main — otherwise you always get the same result.

ex03

Intern« At least this beats coffee-making »

In plain English: an Intern has no attributes at all. It has a single skill: makeForm(formName, target). You give it a string like "robotomy request", it gives you back a pointer to a new RobotomyRequestForm created with new. This is what's called a small "factory".

Files to submit

all the files from ex02Intern.hppIntern.cpp
ex03/Intern.hppdeclarations
#ifndef INTERN_HPP
#define INTERN_HPP

#include <string>
#include "AForm.hpp"

class Intern
{
    private:
        // "Little manufacturing functions", one per form.
        // They ALL have the same signature → we can store them in an array.
        AForm*  createShrubbery(const std::string & target) const;
        AForm*  createRobotomy(const std::string & target) const;
        AForm*  createPardon(const std::string & target) const;

    public:
        Intern();
        Intern(const Intern & other);
        Intern & operator=(const Intern & other);
        ~Intern();

        AForm*  makeForm(const std::string & formName, const std::string & target) const;
};

#endif
Forbidden · the wall of if / else The subject says it clearly: an if (name == "...") ... else if ... else if ... will be rejected during evaluation.
The trick: you already know it (CPP01 · Harl!) In makeForm, build two aligned arrays: an array of names ("shrubbery creation", "robotomy request", "presidential pardon") and an array of pointers to member functions (&Intern::createShrubbery…). Then a single loop: if names[i] == formName, call (this->*creators[i])(target). It's exactly the mechanism behind Harl::complain.

The expected result

example given by the subject
{
    Intern  someRandomIntern;
    AForm*  rrf;

    rrf = someRandomIntern.makeForm("robotomy request", "Bender");
    // ... use rrf ...
    delete rrf;     // ← the caller is responsible for the delete (otherwise a leak)
}

Checklist before the defense

The whole module

  • ☐Compiles with c++ -Wall -Wextra -Werror -std=c++98, Makefile with no relink.
  • ☐All classes in OCF (except exceptions).
  • ☐No implementation in the .hpp files, include guards everywhere.
  • ☐No using namespace, no STL, no printf.
  • ☐Exceptions catchable via catch (std::exception & e).
  • ☐No leak in ex03 (leaks / valgrind).
