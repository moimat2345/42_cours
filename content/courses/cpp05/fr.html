Les 2 choses à comprendre avant de coderles exceptions · le grade « à l'envers »

1 · Une exception, c'est quoi ?

En C, quand ça plante, tu retournes -1 et l'appelant doit vérifier. En C++, tu peux lancer (throw) une erreur : la fonction s'arrête net, et l'erreur remonte les appels jusqu'au premier catch qui sait la gérer. Tout le code entre les deux est sauté.

① try
try { ... }

« J'essaie ce bloc. S'il y a une exception dedans, je veux la rattraper. »

② throw
throw X;

Quelque part (même 5 fonctions plus bas), on lance un objet. Tout s'arrête ici.

③ catch
catch (std::exception & e)

On atterrit ici. e.what() donne le message d'erreur.

l'idée, en résuméexemple générique
try
{
    Bureaucrat bob("Bob", 0);          // grade 0 = invalide → le constructeur lance une exception
    std::cout << "jamais affiché" << std::endl;   // sauté !
}
catch (std::exception & e)            // on attrape TOUTE exception qui hérite de std::exception
{
    std::cout << "Erreur : " << e.what() << std::endl;
}

Pourquoi catch (std::exception & e) attrape ton exception à toi ? Parce que ta classe d'exception va hériter de std::exception (c'est le polymorphisme de CPP04 !). Et tu vas redéfinir sa fonction virtuelle what() pour qu'elle renvoie ton message.

Le sujet impose des noms comme Bureaucrat::GradeTooHighException : le :: veut dire que c'est une classe déclarée à l'intérieur de la classe Bureaucrat (classe imbriquée). Voilà le modèle, tu le réutiliseras pour chaque exception du module :

modèle d'exception imbriquée (dans un .hpp)déclaration
#include <exception>

class Bureaucrat
{
    public:
        // ... le reste de la classe ...

        class GradeTooHighException : public std::exception
        {
            public:
                virtual const char* what() const throw();
        };
};
Le mot bizarre : throw() En C++98, what() est déclarée dans std::exception avec throw() à la fin, qui veut dire « cette fonction ne lance jamais d'exception ». Pour la redéfinir, tu dois recopier exactement la même signature : virtual const char* what() const throw();. Dans le .cpp, tu écriras const char* Bureaucrat::GradeTooHighException::what() const throw() { return "..."; }.
Piège classique On lance un objet : throw GradeTooHighException(); (avec les parenthèses → ça construit un objet temporaire). Pas de new, pas de pointeur. Et on attrape par référence : catch (std::exception & e).

2 · Le grade est « à l'envers »

C'est LE truc qui embrouille tout le monde. 1 = le plus haut grade (le chef), 150 = le plus bas (le stagiaire du stagiaire). Donc :

▲ meilleur pire ▼ 1 75 150

incrementGrade()

  • ↑Le bureaucrate monte en grade → le nombre diminue. 3 devient 2.
  • ✗Si le grade est déjà 1 → GradeTooHighException.

decrementGrade()

  • ↓Le bureaucrate descend → le nombre augmente. 3 devient 4.
  • ✗Si le grade est déjà 150 → GradeTooLowException.

Et pour les formulaires (ex01+) : « avoir un grade suffisant » = ton nombre est plus petit ou égal au nombre requis. Un bureaucrate grade 10 peut signer un formulaire « grade 25 requis ». Un grade 30 ne peut pas.

Bureaucrat« Mommy, when I grow up, I want to be a bureaucrat! »

Ce qu'il faut faire, en français normal : créer une classe Bureaucrat qui a un nom (qui ne change jamais) et un grade entre 1 et 150. Tu peux faire monter ou descendre son grade. Dès que quelque chose essaie de mettre un grade hors de [1, 150] — à la construction ou avec increment/decrement — tu lances une exception. Et tu peux l'afficher avec std::cout << bureaucrat.

Le header à toi le .cpp

ex00/Bureaucrat.hppdéclarations
#ifndef BUREAUCRAT_HPP
#define BUREAUCRAT_HPP

#include <string>
#include <iostream>
#include <exception>

class Bureaucrat
{
    private:
        const std::string   _name;      // const → fixé à la construction, plus jamais modifié
        int                 _grade;     // 1 (meilleur) ... 150 (pire)

    public:
        // --- Forme canonique ---
        Bureaucrat();                                   // nom/grade par défaut de ton choix (valide !)
        Bureaucrat(const std::string & name, int grade); // peut lancer une exception
        Bureaucrat(const Bureaucrat & other);
        Bureaucrat & operator=(const Bureaucrat & other);
        ~Bureaucrat();

        // --- Getters (noms imposés) ---
        const std::string & getName() const;
        int                 getGrade() const;

        // --- Changer de grade ---
        void    incrementGrade();   // grade - 1  (peut lancer GradeTooHighException)
        void    decrementGrade();   // grade + 1  (peut lancer GradeTooLowException)

        // --- Exceptions (noms imposés) ---
        class GradeTooHighException : public std::exception
        {
            public:
                virtual const char* what() const throw();
        };
        class GradeTooLowException : public std::exception
        {
            public:
                virtual const char* what() const throw();
        };
};

// Surcharge de << : fonction LIBRE (hors de la classe), pas une méthode
std::ostream & operator<<(std::ostream & out, const Bureaucrat & b);

#endif

Ce que chaque fonction doit faire

  • →Constructeur (name, grade) : si grade < 1 → throw TooHigh ; si grade > 150 → throw TooLow ; sinon on stocke.
  • →increment / decrement : vérifie avant de modifier, lance la même exception que le constructeur.
  • →what() : retourne juste une chaîne, ex. "Grade too high".
  • →operator<< : écrit dans out et retourne out (pour pouvoir enchaîner les <<).

Pièges

  • !Nom const + operator= : impossible de réassigner un const. Dans operator=, tu ne copies que le grade. C'est normal et attendu.
  • !Un const s'initialise uniquement dans la liste d'initialisation : : _name(name), pas dans le corps du constructeur.
  • !Monter en grade = soustraire. Relis deux fois.

Le résultat attendu

Le format de << est imposé (au caractère près, avec le point final) :

format imposé
<name>, bureaucrat grade <grade>.

Le reste (messages d'erreur, tests) est libre. Ton main.cpp doit prouver que tout marche. Exemple de sortie d'un bon main :

./bureaucratexemple

Bob, bureaucrat grade 2.
Bob, bureaucrat grade 1.       ← après incrementGrade()

--- Test 2 : construction invalide ---

Ce que ton main doit tester (le correcteur va regarder) Création valide · création avec 0 · création avec 151 · increment jusqu'à dépasser 1 · decrement jusqu'à dépasser 150 · l'affichage avec <<. Chaque cas dangereux dans son propre try/catch, sinon la première exception arrête tous les tests suivants.

ex01/Bureaucrat.hpp — les ajoutsdéclarations

    public:
        void    signForm(Form & form);   // PAS const : signer modifie le formulaire
};
Pourquoi « class Bureaucrat; » tout seul ? Form a besoin de connaître Bureaucrat (pour beSigned), et Bureaucrat a besoin de connaître Form (pour signForm). Si chaque .hpp fait #include de l'autre, ça tourne en rond et ça ne compile pas. Solution : dans le .hpp, on dit juste « cette classe existe » (class Form;). Ça suffit pour déclarer une référence Form &. Le vrai #include "Form.hpp", tu le mets dans le .cpp, là où tu utilises vraiment ses fonctions.

Qui appelle qui ?

Form::beSigned(bureaucrat)

  • 1Compare le grade du bureaucrate au grade requis pour signer.
  • 2Assez bon (grade <= requis) → _signed = true.
  • 3Trop bas → throw Form::GradeTooLowException().
  • ·N'affiche rien. C'est le « moteur ».

Bureaucrat::signForm(form)

  • 1Appelle form.beSigned(*this) dans un try.
  • 2Ça passe → affiche <bureaucrat> signed <form>.
  • 3Exception attrapée → affiche <bureaucrat> couldn't sign <form> because <reason>. (reason = e.what()).
  • ·C'est l'« interface » qui affiche.

Le schéma des classes

« Une façon est plus élégante que l'autre »

Le sujet te laisse choisir où vérifier les conditions (signé ? grade suffisant ?). Deux options :

✗ Option lourde

  • ·Chaque formulaire concret redéfinit execute() et refait les mêmes vérifications.
  • ·3 fois le même code copié-collé. Un oubli = un bug.

✓ Option élégante

  • 1AForm::execute() (non virtuelle) fait les vérifications une seule fois et lance l'exception si besoin.
  • 2Si tout va bien, elle appelle une fonction virtuelle pure (ex. executeAction()) que chaque formulaire implémente avec son action à lui.
  • ★Bonus : c'est cette fonction = 0 qui rend AForm abstraite.

Les headers

ex02/AForm.hppdéclarations
#ifndef AFORM_HPP
#define AFORM_HPP

#include <string>
#include <iostream>
#include <exception>

class Bureaucrat;

class AForm
{
    private:                            // toujours PRIVATE, et ils restent dans la classe de base
        const std::string   _name;
        bool                _signed;
        const int           _gradeToSign;
        const int           _gradeToExecute;

    protected:
        // L'action propre à chaque formulaire. "= 0" → AForm devient abstraite.
        virtual void    executeAction() const = 0;

    public:
        AForm();
        AForm(const std::string & name, int gradeToSign, int gradeToExecute);
        AForm(const AForm & other);
        AForm & operator=(const AForm & other);
        virtual ~AForm();               // VIRTUEL : on détruira des enfants via un AForm*

        const std::string & getName() const;
        bool                getSigned() const;
        int                 getGradeToSign() const;
        int                 getGradeToExecute() const;

        void    beSigned(const Bureaucrat & b);
        void    execute(Bureaucrat const & executor) const;   // signature imposée

        class GradeTooHighException : public std::exception
        { public: virtual const char* what() const throw(); };
        class GradeTooLowException : public std::exception
        { public: virtual const char* what() const throw(); };
        class FormNotSignedException : public std::exception      // nouvelle !
        { public: virtual const char* what() const throw(); };
};

std::ostream & operator<<(std::ostream & out, const AForm & f);

#endif

AForm::execute(executor)

  • 1Pas signé → throw FormNotSignedException()
  • 2Grade de l'exécuteur > grade d'exécution → throw GradeTooLowException()
  • 3Sinon → executeAction() (le polymorphisme choisit la bonne version).

Bureaucrat::executeForm(form)

  • 1Même idée que signForm : try { form.execute(*this); }
  • 2OK → <bureaucrat> executed <form>
  • 3Exception → un message d'erreur explicite (libre), avec e.what().
Les outils C++ dont tu auras besoin dans les .cpp Shrubbery : #include <fstream> puis std::ofstream pour créer/écrire le fichier (en C++98, le constructeur veut un const char* → (_target + "_shrubbery").c_str()). Pense au cas où le fichier ne s'ouvre pas.
Robotomy : std::rand() de <cstdlib>, un nombre pair ou impair = 50/50. Initialise la graine une seule fois avec std::srand(std::time(0)) (<ctime>), par ex. au début du main — sinon tu as toujours le même résultat.
