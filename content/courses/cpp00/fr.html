Le projet en bref

CPP00 est ta première rencontre avec le C++. La couverture du sujet l'annonce : namespaces, classes, fonctions membres, flux d'entrée-sortie, listes d'initialisation, static, const et quelques autres bases. 03

Namespaces, flux et std::string

Les namespaces. En C, tous les noms vivent dans le même espace : deux fonctions ne peuvent pas s'appeler pareil. En C++, un namespace est un espace de noms, et la bibliothèque standard vit dans le namespace std. L'opérateur :: (« portée ») dit où chercher : std::cout se lit « le cout de std ».

namespace.cpp
#include <iostream>

namespace Bank
{
    const int rate = 3;
}

int main(void)
{
    std::cout << Bank::rate << std::endl;   // affiche 3
    return (0);
}
⚠️

Pas de using namespace std;. Le sujet l'interdit (note -42, p. 4). Le compilateur, lui, l'accepte sans broncher : rien ne te prévient, c'est l'évaluateur qui sanctionne. Écris toujours le préfixe std::.

Écrire : std::cout. Avec #include <iostream>, l'opérateur << envoie une valeur dans le flux de sortie et rend ce flux : on peut donc les enchaîner. Pas de %d ni de %s : le flux connaît le type de ce que tu lui donnes. std::endl écrit un saut de ligne et vide le tampon ; le sujet veut un saut de ligne à la fin de chaque message (p. 3).

Lire : std::cin et std::getline. std::cin >> x lit « un mot » (jusqu'au prochain espace ou saut de ligne). std::getline(std::cin, ligne) lit une ligne entière dans une std::string, sans le '\n'. Les deux rendent le flux, qui vaut « faux » dans une condition quand la lecture a échoué, par exemple à la fin de l'entrée (Ctrl-D dans un terminal) :

main.cpp
#include <iostream>
#include <string>

int main(void)
{
    std::string name;

    std::cout << "Login: ";
    if (!std::getline(std::cin, name))   // fin de l'entrée : on s'arrête proprement
        return (1);
    std::cout << "Hello " << name << std::endl;
    return (0);
}

Les chaînes : std::string. Plus de strlen ni de strcmp : une std::string sait faire tout cela, avec #include <string>. Le sujet renvoie vers les pages de référence de string et de iomanip (p. 10) ; cppreference.com en propose de très complètes (std::string, std::setw).

04

Les classes

Une classe regroupe des attributs (les données) et des méthodes (les fonctions qui travaillent dessus). Un objet est une instance de la classe : Student s("mateon", 3); fabrique un objet. Comme en C avec les struct, mais les fonctions sont à l'intérieur.

public

  • •Ce que le reste du programme a le droit d'utiliser
  • •Les méthodes qu'on appelle depuis main
  • •Les accesseurs (getLogin…)

private

  • •Ce que seule la classe utilise
  • •Presque tous les attributs
  • •Les fonctions d'aide internes

Le sujet fixe la règle de répartition (p. 9) : tout ce qui sert toujours à l'intérieur de la classe est private, tout ce qui peut servir à l'extérieur est public. Dans une class, tout est privé tant que tu n'écris pas public: ; dans une struct, c'est l'inverse. L'accès à un membre privé depuis l'extérieur ne compile pas. Le cours public vs private détaille cette différence et l'encapsulation avec une classe Contact.

Le header déclare, le .cpp définit. Le .hpp contient la déclaration de la classe, avec ses gardes d'inclusion ; le .cpp contient le code des méthodes, préfixées par le nom de la classe et ::. Une implémentation dans un header vaut 0 à l'exercice (p. 4). Un exemple minuscule, sans rapport avec le module :

Student.hpp
#ifndef STUDENT_HPP
# define STUDENT_HPP

# include <string>

class Student
{
public:
    Student(const std::string &login, int level);   // constructeur
    ~Student(void);                                 // destructeur

    const std::string &getLogin(void) const;
    int getLevel(void) const;
    void levelUp(void);

private:
    const std::string _login;   // fixé à la construction, ne change plus
    int _level;
};

#endif
Student.cpp
#include "Student.hpp"

Student::Student(const std::string &login, int level) : _login(login), _level(level)
{
}

void Student::levelUp(void)
{
    this->_level++;   // this : l'objet sur lequel on a appelé la méthode
}

// le destructeur et les accesseurs s'écrivent de la même façon

Constructeur et destructeur. Le constructeur porte le nom de la classe, n'a pas de type de retour et s'exécute à la création de l'objet. Le destructeur (~Student) s'exécute quand l'objet disparaît, par exemple à la fin du bloc où il a été déclaré.

this. Dans une méthode, this est un pointeur vers l'objet courant : this->_level désigne l'attribut de l'objet sur lequel tu as appelé la méthode. Écrire juste _level revient au même ; this-> lève le doute quand un paramètre porte le même nom que l'attribut.

La liste d'initialisation. Après les : du constructeur, _login(login), _level(level) initialise les attributs avant l'exécution du corps. Elle est obligatoire pour un attribut const (ou une référence), et c'est la bonne habitude pour les autres :

clang (macOS) · message de compilation
error: constructor for 'Account' must explicitly initialize the const member '_id'
error: cannot assign to non-static data member '_id' with const-qualified type 'const int'

Les attributs sont initialisés dans l'ordre où ils sont déclarés dans la classe, pas dans l'ordre de ta liste. Avec -Wall -Werror, une liste dans le désordre est une erreur de compilation : field '_b' will be initialized after field '_a' (constaté avec clang).

const, deux usages. Un attribut const ne change plus après la construction. Une méthode const (le mot après les parenthèses : int getLevel(void) const;) promet de ne pas modifier l'objet : modifier un attribut dedans ne compile pas (cannot assign to non-static data member within const member function). Rends const tout ce qui ne modifie rien, les accesseurs en tête.

💡

Un tableau d'objets demande un constructeur par défaut. Si ta classe PhoneBook a un attribut Contact _contacts[8];, chaque case est construite sans argument : sans constructeur sans paramètre, ça ne compile pas (which does not have a default constructor). Tant que tu ne déclares aucun constructeur dans Contact, le compilateur t'en fournit un.

05

Membres static

Un attribut ordinaire existe une fois par objet. Un attribut static existe une seule fois pour toute la classe : tous les objets le partagent, et il existe même quand aucun objet n'a été créé. C'est la bonne place pour un compteur d'objets ou un total. Une méthode static appartient elle aussi à la classe, pas à un objet : elle n'a pas de this et s'appelle sans objet, avec Classe::methode().

Ticket.hpp
#ifndef TICKET_HPP
# define TICKET_HPP

class Ticket
{
public:
    Ticket(void);

    int getNumber(void) const;
    static int getCount(void);   // méthode statique : s'appelle sans objet

private:
    static int _count;           // UN seul exemplaire pour toute la classe
    int _number;                 // un exemplaire par ticket
};

#endif
Ticket.cpp
#include "Ticket.hpp"

int Ticket::_count = 0;          // la définition, écrite UNE fois, dans un .cpp

Ticket::Ticket(void) : _number(_count + 1)
{
    _count++;                    // partagé : tous les tickets voient la même valeur
}

int Ticket::getCount(void)
{
    return (_count);             // pas de this ici : seulement des membres static
}

Avec ce code, Ticket::getCount() vaut 0 avant tout ticket, puis 2 après deux tickets créés (vérifié). Trois erreurs classiques, vérifiées avec clang sur macOS :

Ce que tu faisCe que tu obtiens
Tu déclares static int _count; mais tu n'écris jamais int Ticket::_count = 0;Erreur de l'éditeur de liens : Undefined symbols … "Ticket::_count"
Tu écris la définition dans le .hpp, inclus par deux .cppduplicate symbol 'Ticket::_count'. Et une implémentation dans un header vaut 0 (p. 4)

C'est exactement le mécanisme d'ex02 : la classe Account garde dans quatre membres statiques le nombre de comptes, le total des montants, le nombre de dépôts et le nombre de retraits, partagés par tous les comptes. Joue avec la démo : le journal imite le fichier de log du sujet (ses lignes sont détaillées dans la section ex02).

Démo (nécessite JavaScript) : des boutons pour créer un compte avec un montant, déposer, retirer et afficher l'état de comptes numérotés. Les quatre compteurs static (nbAccounts, totalAmount, totalNbDeposits, totalNbWithdrawals) se mettent à jour et le journal s'écrit au fil des opérations.

Exemple sans JavaScript : on crée deux comptes de 42 et 54, puis on dépose 10 sur le premier.
Après les deux créations : nbAccounts = 2, totalAmount = 96.
Après le dépôt de 10 sur le compte 0 : totalAmount = 106, totalNbDeposits = 1.

Ce que la démo te montre, à reproduire toi-même :

1Un compteur partagé. Crée un compte de 42 puis un de 54 : nbAccounts passe à 2 et totalAmount à 96. Aucun des deux comptes ne « possède » ces valeurs, elles sont à la classe.
2Un dépôt touche le compte et le total. Dépose 10 sur le compte 0 : son montant passe à 52, totalAmount à 106 et totalNbDeposits à 1.
3Un retrait refusé ne change rien. Retire plus que le solde : une ligne withdrawal:refused est écrite, mais aucun compteur ne bouge.

ex00 · Megaphone

Le sujet (p. 8) demande « un programme qui produit la sortie suivante » : il met ses arguments en majuscules, et si on ne lui en donne aucun, il affiche un message de « bruit ». Il précise « Solve the exercises in a C++ manner » : std::cout et std::string, pas de puts ni de printf.

Fichiers à rendre (p. 8), dans ex00/ : Makefile et megaphone.cpp.

Le résultat attendu, tel que le sujet le donne :

sortie imposée par le sujet (p. 8)
$>./megaphone "shhhhh... I think the students are asleep..."
SHHHHH... I THINK THE STUDENTS ARE ASLEEP...
$>./megaphone Damnit " ! " "Sorry students, I thought this thing was off."
DAMNIT ! SORRY STUDENTS, I THOUGHT THIS THING WAS OFF.
$>./megaphone
* LOUD AND UNBEARABLE FEEDBACK NOISE *
$>

Trois détails se lisent dans ces exemples :

1Les arguments sont collés tels quels. Dans le deuxième exemple, Damnit, " ! " (avec ses espaces) et la phrase donnent DAMNIT ! SORRY… : le programme n'ajoute aucun espace entre deux arguments.
2Sans argument, un message fixe. Dans main, argc == 1 veut dire « aucun argument » : argv[0] est le nom du programme.
3Un saut de ligne à la fin. Le sujet l'exige pour toute sortie (p. 3), y compris pour le message de bruit.

Passer en majuscule. std::toupper (header <cctype>) prend un caractère et rend la version majuscule, mais comme un int : envoyé tel quel dans std::cout, il s'afficherait comme un nombre (65 au lieu de A, vérifié). Reconvertis-le en char avant de l'écrire. Le standard C demande que l'argument soit représentable par un unsigned char (ou vaille EOF) : convertis d'abord le caractère, c'est le cas sûr, notamment pour les caractères accentués.

extrait · une idée, pas le programme
std::cout << static_cast<char>(std::toupper(static_cast<unsigned char>(c)));

Le Makefile. Le sujet dit que les règles du Makefile sont celles du C (p. 4) ; les règles exactes sont dans la Norme, à relire. Un squelette qui compile avec c++, ne reconstruit rien quand rien n'a changé (vérifié avec make deux fois de suite) et fournit all, clean, fclean et re :

Makefile
NAME     = megaphone
CXX      = c++
CXXFLAGS = -Wall -Wextra -Werror -std=c++98
SRC      = megaphone.cpp
OBJ      = $(SRC:.cpp=.o)

all: $(NAME)

$(NAME): $(OBJ)
	$(CXX) $(CXXFLAGS) $(OBJ) -o $(NAME)

%.o: %.cpp
	$(CXX) $(CXXFLAGS) -c $< -o $@

clean:
	rm -f $(OBJ)

fclean: clean
	rm -f $(NAME)

re: fclean all

.PHONY: all clean fclean re

Pour les exercices suivants, seule la liste SRC change (et le NAME : le sujet d'ex01 demande « a relevant name » pour l'exécutable, p. 10). Attention : cette règle ne dépend pas des .hpp. Si tu modifies un header, make ne recompile rien tout seul (constaté) : lance make re, ou ajoute tes headers comme dépendances de la règle %.o.

ex01 · My Awesome PhoneBook

Un répertoire « façon années 80 » (p. 9), en ligne de commande. Fichiers à rendre (p. 9), dans ex01/ : Makefile, *.cpp, *.{h, hpp}. Le nom de l'exécutable est libre mais doit être pertinent (p. 10).

Classes

PhoneBook et Contact

Deux classes, et le répertoire doit être une instance de PhoneBook, chaque contact une instance de Contact (p. 9). Tu es libre de les dessiner, avec la règle public/private de la section classes.

Stockage

8 contacts, pas de new

PhoneBook a un tableau de contacts, 8 au maximum. Un 9e contact remplace le plus ancien. L'allocation dynamique est interdite (p. 9).

ADD

Enregistrer un contact

Les champs se saisissent un par un : prénom, nom, surnom, numéro de téléphone, « darkest secret ». Aucun champ ne peut être vide (p. 10).

SEARCH

Afficher un contact

Liste de 4 colonnes (index, prénom, nom, surnom), puis demande d'un index, puis affichage du contact, un champ par ligne. Index faux : à toi de définir un comportement pertinent (p. 10).

EXIT

Quitter

Le programme s'arrête et les contacts sont perdus. Toute autre saisie est ignorée ; après chaque commande exécutée, le programme en attend une autre (p. 10).

Les headers. Voici une façon de les écrire : uniquement des déclarations, deux classes, rien de plus. Les noms sont des suggestions (le sujet ne dicte aucun nom de méthode ici).

#ifndef PHONEBOOK_HPP
# define PHONEBOOK_HPP

# include "Contact.hpp"

class PhoneBook
{
public:
    PhoneBook(void);

    void add(void);             // la commande ADD
    void search(void) const;    // la commande SEARCH

private:
    Contact _contacts[8];       // un tableau fixe : pas de new

};

#endif

Le plus ancien se remplace en cercle. Tant que le répertoire n'est pas plein, le contact va dans la première case libre. Ensuite, il remplace le plus ancien (pas le dernier ajouté !). Une position _next qui avance de 1 et revient à 0 après 7 (le calcul (_next + 1) % 8) suffit : la première case écrasée est la 0, puis la 1, etc.

L'affichage de SEARCH. Chaque colonne fait 10 caractères, alignée à droite, les colonnes sont séparées par | (p. 10). Le texte trop long est tronqué et son dernier caractère visible est remplacé par un point : pour Alexandria-Long, tu affiches Alexandri. (9 caractères puis le point). Un texte de 10 caractères exactement n'est pas touché. Le sujet ne parle pas d'une barre au début ou à la fin de la ligne : c'est ton choix. Manipule la démo, puis lis le code équivalent :

Démo (nécessite JavaScript) : un formulaire (prénom, nom, surnom) qui ajoute des lignes à un tableau façon PhoneBook, avec des colonnes de 10 caractères alignées à droite et séparées par |. Tout texte de plus de 10 caractères est tronqué à 9 caractères suivis d'un point. À côté, le code std::setw(10) équivalent.

Exemple sans JavaScript : le prénom Alexandria-Long s'affiche Alexandri. ; le prénom Bob s'affiche Bob (7 espaces puis Bob).

     Index|First Name| Last Name|  Nickname
         0|Alexandri.|       Bob|     Bobby

Ce que la démo te montre, à reproduire toi-même :

1Tronquer, c'est ton travail. Tape Alexandria-Long comme prénom : setw n'a rien coupé, c'est un substr(0, 9) suivi d'un point qui donne Alexandri.. La colonne fait toujours exactement 10 caractères.
2Compléter, c'est setw. Tape Bob : setw(10) ajoute les 7 espaces à gauche.
3Huit contacts, pas neuf. Ajoute-en neuf : le neuvième prend la place de l'index 0, le plus ancien.
4Un champ vide est refusé. Laisse un champ vide : le contact n'est pas ajouté, comme l'exige le sujet.

ex02 · The Job Of Your Dreams

L'histoire du sujet (p. 11-12) : un fichier source a été effacé par erreur dans une banque, GlobalBanksters United. Tu retrouves Account.hpp et tests.cpp, plus un fichier de log. Compiler tests.cpp révèle que le fichier manquant est Account.cpp. Ta mission : le réécrire pour que la sortie du programme corresponde parfaitement au log, horodatages exceptés (p. 12).

Fichiers à rendre (p. 11), dans ex02/ : Makefile, Account.cpp, Account.hpp, tests.cpp. Account.hpp, tests.cpp et le log sont à télécharger sur la page du module, sur l'intranet (p. 11). Cet exercice n'est pas obligatoire pour valider le module (p. 12). Le sujet ajoute que l'ordre d'appel des destructeurs peut varier selon le compilateur et le système, donc l'ordre des lignes closed aussi (p. 12).

Tout ce que la section static t'a appris est ici : quatre compteurs partagés (à définir dans ton Account.cpp, avec leur valeur de départ), quatre accesseurs statiques, une méthode statique d'affichage, et une méthode statique privée _displayTimestamp que toutes les autres utilisent. Le constructeur par défaut est privé : on ne crée un compte qu'avec un dépôt initial. displayStatus et checkAmount sont const : elles ne modifient pas le compte.

Le log est ta spécification. Chaque appel écrit une ligne : un horodatage entre crochets, puis des paires clé:valeur séparées par des ;. Pièges classiques

⚠️

Tronquer sans casser l'alignement. Un texte de plus de 10 caractères donne 9 caractères + un point = 10 en tout. Un texte de 10 caractères exactement reste intact ; 012345678. pour 11 caractères (vérifié). Ne tronque pas à 10 caractères avant d'ajouter le point : tu aurais 11 caractères et tout glisse. N'oublie pas que setw ne coupe jamais et ne vaut que pour l'élément suivant.

⚠️

Les accents comptent double. std::string et setw comptent des octets. En UTF-8, é en pèse 2 : setw(10) << "é" écrit 8 espaces et la colonne paraît faite de 9 caractères ; un nom de six é (12 octets) est coupé à 9 octets, au milieu d'un caractère (vérifié). Le sujet ne dit rien là-dessus : assume tes choix (par exemple n'accepter que de l'ASCII) et sois prêt à les expliquer.

⚠️

std::cin et la fin de fichier (Ctrl-D). Quand l'entrée se ferme, std::getline échoue, et il échoue à tous les appels suivants. Une boucle while (1) qui ne teste pas le retour tourne à l'infini sur des commandes vides ; si l'entrée finit sans saut de ligne (printf 'ADD' | ./phonebook), la chaîne garde même sa dernière valeur et le programme rejoue ADD sans fin (vérifié). Teste toujours if (!std::getline(std::cin, s)) et quitte proprement. Essaie < /dev/null et Ctrl-D à chaque invite : en début de ligne, Ctrl-D ferme l'entrée dans un terminal (vérifié).

⚠️

La saisie vide refusée. « A saved contact can't have empty fields » (p. 10) : redemande le champ, ou annule le ADD. Mais une boucle « redemande tant que c'est vide » doit aussi sortir quand l'entrée est fermée, sinon elle tourne à l'infini (vérifié). Le sujet ne dit rien d'un champ rempli d'espaces : empty() le juge non vide, c'est à toi de décider. Côté commande : seules ADD, SEARCH et EXIT sont acceptées, toute autre saisie est ignorée (p. 10).

⚠️

L'indice hors limites. Lis l'index comme une ligne (std::getline), puis valide-le toi-même : vide, pas un chiffre, négatif, supérieur à 7, ou valide mais dans une case encore vide. Avec std::cin >> index, une saisie comme abc met le flux en échec et laisse le texte dans le tampon : toutes les lectures suivantes échouent tant que tu n'appelles pas std::cin.clear() et que tu ne vides pas la ligne (vérifié). Ne confonds pas « index 0 » avec « pas un nombre » si tu utilises atoi, qui rend 0 dans les deux cas.

⚠️

std::getline après std::cin >>. std::cin >> n s'arrête avant le saut de ligne et le laisse dans le tampon : le std::getline suivant lit une ligne vide (vérifié). Le plus simple : n'utilise que std::getline, y compris pour les commandes et l'index.

⚠️

Huit contacts maximum. Le tableau est fixe (new est interdit ici, p. 9). Le 9e contact remplace le plus ancien, pas le dernier ajouté. Teste en ajoutant 9 puis 10 contacts, puis affiche la liste : les index 0 et 1 doivent être les deux nouveaux, et SEARCH ne doit afficher que des cases remplies.

⚠️

Le timestamp du journal. Il faut des zéros de remplissage : sans eux, le 8 novembre 2026 à 20:40:28 s'écrirait 2026118_204028 au lieu de 20261108_204028 (vérifié). Avec std::setfill('0'), attention : le remplissage est collant. Après lui, un setw(5) << "Bob" écrit 00Bob (vérifié) ; remets std::setfill(' ') ou préfère std::strftime. Et rappelle-toi que le log diffère du tien par ses horodatages seulement (p. 12).

⚠️

Les pièges de compilation. std::toupper demande <cctype> : sur clang/macOS, un programme qui n'inclut que <iostream> compile quand même, mais rien ne le garantit ailleurs (à vérifier avec le compilateur de ton école). Un membre statique jamais défini, ou défini dans le header, casse l'édition de liens. Une liste d'initialisation dans le désordre est une erreur avec -Werror. Une implémentation dans un .hpp ou l'absence de garde d'inclusion font 0 (p. 4).

Comment je l'ai fait

Pour megaphone, je parcours les arguments caractère par caractère, chaque lettre est passée en majuscule, sans rien ajouter entre les arguments ; sans argument, j'affiche le message de bruit. Dans le PhoneBook, Contact ne contient que cinq chaînes privées avec leurs accesseurs.
