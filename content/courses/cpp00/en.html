01

The project in short

CPP00 is your first meeting with C++. The subject's cover announces it: namespaces, classes, member functions, stdio streams, initialization lists, static, const and a few other basics. You write three programs of increasing difficulty: a megaphone that shouts its arguments in uppercase (ex00, p. 8), a command-line phonebook (ex01, p. 9-10), and the rebuilding of a lost file, Account.cpp, from its header and a log file (ex02, p. 11-12).

The module does not ask for deep theory: it makes you handle the basic building blocks of object-oriented programming, in C++98. The course follows this order: the tools (streams, std::string), classes, static, then each exercise.

📖

The page numbers in parentheses, like (p. 8), are the ones printed at the bottom of the subject's pages (version 11.0): the cover has none and the table of contents is page 1. Keep the PDF open next to this page: this course explains the subject, it does not replace it.

Three changes of reflex compared to C sum up the module:

1Streams instead of printf. You write with std::cout, read with std::cin and std::getline, and format with std::setw. printf is forbidden (p. 3).
2Classes instead of loose functions. Data and the functions that handle it live together, with what is private and what is public. Each class has its own .hpp and .cpp.
3static members. A piece of data shared by every object of a class, like the number of open accounts: that is the heart of ex02.

03

Namespaces, streams and std::string

Namespaces. In C, every name lives in the same space: two functions cannot have the same name. In C++, a namespace is a named space, and the standard library lives in the namespace std. The :: operator ("scope") says where to look: std::cout reads as "the cout of std".

namespace.cpp
#include <iostream>

namespace Bank
{
    const int rate = 3;
}

int main(void)
{
    std::cout << Bank::rate << std::endl;   // prints 3
    return (0);
}
⚠️

No using namespace std;. The subject forbids it (grade -42, p. 4). The compiler, on the other hand, accepts it without complaint: nothing warns you, the evaluator is the one who penalizes. Always write the std:: prefix.

Writing: std::cout. With #include <iostream>, the << operator sends a value into the output stream and returns that stream: you can chain them. No %d or %s: the stream knows the type of what you give it. std::endl writes a newline and flushes the buffer; the subject wants a newline at the end of every message (p. 3).

Reading: std::cin and std::getline. std::cin >> x reads "a word" (up to the next space or newline). std::getline(std::cin, line) reads a whole line into a std::string, without the '\n'. Both return the stream, which counts as "false" in a condition when the read failed, for example at the end of the input (Ctrl-D in a terminal):

main.cpp
#include <iostream>
#include <string>

int main(void)
{
    std::string name;

    std::cout << "Login: ";
    if (!std::getline(std::cin, name))   // end of input: stop cleanly
        return (1);
    std::cout << "Hello " << name << std::endl;
    return (0);
}

Strings: std::string. No more strlen or strcmp: a std::string can do all of that, with #include <string>. The subject points to the reference pages for string and iomanip (p. 10); cppreference.com has very complete ones (std::string, std::setw).

Formatting: <iomanip>. std::setw(n) sets the minimum width of the next item written: if it is shorter, the stream pads it on the left with spaces (right-aligned by default). Three things to know, checked with clang on macOS:

By contrast, std::setfill(c) (the padding character) stays active until you change it: we come back to that in the pitfalls.

04

Classes

A class groups attributes (the data) and methods (the functions that work on it). An object is an instance of the class: Student s("mateon", 3); builds an object. Like a C struct, but the functions are inside.

public

  • •What the rest of the program is allowed to use
  • •The methods you call from main
  • •The accessors (getLogin…)

private

  • •What only the class itself uses
  • •Almost all the attributes
  • •Internal helper functions

The subject sets the rule for the split (p. 9): anything that will always be used inside a class is private, anything that can be used outside is public. In a class, everything is private until you write public:; in a struct, it is the opposite. Accessing a private member from outside does not compile. The public vs private course explains this difference and encapsulation with a Contact class.

The header declares, the .cpp defines. The .hpp holds the class declaration, with its include guards; the .cpp holds the code of the methods, prefixed by the class name and ::. An implementation in a header is worth 0 for the exercise (p. 4). A tiny example, unrelated to the module:

Student.hpp
#ifndef STUDENT_HPP
# define STUDENT_HPP

# include <string>

class Student
{
public:
    Student(const std::string &login, int level);   // constructor
    ~Student(void);                                 // destructor

    const std::string &getLogin(void) const;
    int getLevel(void) const;
    void levelUp(void);

private:
    const std::string _login;   // set at construction, never changes
    int _level;
};

#endif
Student.cpp
#include "Student.hpp"

Student::Student(const std::string &login, int level) : _login(login), _level(level)
{
}

void Student::levelUp(void)
{
    this->_level++;   // this: the object the method was called on
}

// the destructor and the accessors are written the same way

Constructor and destructor. The constructor has the name of the class, has no return type, and runs when the object is created. The destructor (~Student) runs when the object goes away, for example at the end of the block where it was declared.

this. Inside a method, this is a pointer to the current object: this->_level is the attribute of the object you called the method on. Writing just _level is the same; this-> removes the doubt when a parameter has the same name as the attribute.

The initialization list. After the : of the constructor, _login(login), _level(level) initializes the attributes before the body runs. It is mandatory for a const attribute (or a reference), and it is the right habit for the others:

clang (macOS) · compiler messages
error: constructor for 'Account' must explicitly initialize the const member '_id'
error: cannot assign to non-static data member '_id' with const-qualified type 'const int'

Attributes are initialized in the order they are declared in the class, not in the order of your list. With -Wall -Werror, a list in the wrong order is a compile error: field '_b' will be initialized after field '_a' (observed with clang).

const, two uses. A const attribute does not change after construction. A const method (the word after the parentheses: int getLevel(void) const;) promises not to modify the object: modifying an attribute inside does not compile (cannot assign to non-static data member within const member function). Make const everything that modifies nothing, starting with the accessors.

💡

An array of objects needs a default constructor. If PhoneBook has an attribute Contact _contacts[8];, each slot is built with no arguments: without a constructor that takes no parameters, it does not compile (which does not have a default constructor). As long as you declare no constructor in Contact, the compiler provides one for you.

05

static members

An ordinary attribute exists once per object. A static attribute exists once for the whole class: every object shares it, and it exists even when no object has been created. It is the right place for an object counter or a total. A static method belongs to the class too, not to an object: it has no this and is called without an object, with Class::method().

Ticket.hpp
#ifndef TICKET_HPP
# define TICKET_HPP

class Ticket
{
public:
    Ticket(void);

    int getNumber(void) const;
    static int getCount(void);   // static method: called without an object

private:
    static int _count;           // ONE copy for the whole class
    int _number;                 // one copy per ticket
};

#endif
Ticket.cpp
#include "Ticket.hpp"

int Ticket::_count = 0;          // the definition, written ONCE, in a .cpp

Ticket::Ticket(void) : _number(_count + 1)
{
    _count++;                    // shared: every ticket sees the same value
}

int Ticket::getCount(void)
{
    return (_count);             // no this here: only static members
}

With this code, Ticket::getCount() is 0 before any ticket, then 2 after two tickets are created (checked). Three classic errors, checked with clang on macOS:

What you doWhat you get
You declare static int _count; but never write int Ticket::_count = 0;Linker error: Undefined symbols … "Ticket::_count"
You write the definition in the .hpp, included by two .cpp filesduplicate symbol 'Ticket::_count'. And an implementation in a header is worth 0 (p. 4)
You use this or a non-static attribute inside a static methodinvalid use of 'this' outside of a non-static member function, or invalid use of member … in static member function

This is exactly the mechanism of ex02: the Account class keeps in four static members the number of accounts, the total of the amounts, the number of deposits and the number of withdrawals, shared by all the accounts. Play with the demo: the log imitates the subject's log file (its lines are detailed in the ex02 section).

Demo (requires JavaScript): buttons to create an account with an amount, deposit, withdraw and show the status of numbered accounts. The four static counters (nbAccounts, totalAmount, totalNbDeposits, totalNbWithdrawals) update and the log is written as operations happen.

Example without JavaScript: create two accounts of 42 and 54, then deposit 10 into the first one.
After the two creations: nbAccounts = 2, totalAmount = 96.
After depositing 10 into account 0: totalAmount = 106, totalNbDeposits = 1.

What the demo shows you, to reproduce yourself:

1A shared counter. Create an account of 42 then one of 54: nbAccounts becomes 2 and totalAmount becomes 96. Neither account "owns" these values, they belong to the class.
2A deposit touches the account and the total. Deposit 10 into account 0: its amount becomes 52, totalAmount becomes 106 and totalNbDeposits becomes 1.
3A refused withdrawal changes nothing. Withdraw more than the balance: a withdrawal:refused line is written, but no counter moves.

ex00 · Megaphone

The subject (p. 8) asks for "a program that produces the following output": it puts its arguments in uppercase, and if you give it none, it prints a "noise" message. It adds "Solve the exercises in a C++ manner": std::cout and std::string, no puts or printf.

Files to turn in (p. 8), in ex00/: Makefile and megaphone.cpp.

The expected result, as the subject gives it:

output required by the subject (p. 8)
$>./megaphone "shhhhh... I think the students are asleep..."
SHHHHH... I THINK THE STUDENTS ARE ASLEEP...
$>./megaphone Damnit " ! " "Sorry students, I thought this thing was off."
DAMNIT ! SORRY STUDENTS, I THOUGHT THIS THING WAS OFF.
$>./megaphone
* LOUD AND UNBEARABLE FEEDBACK NOISE *
$>

Three details can be read in these examples:

1Arguments are glued together as is. In the second example, Damnit, " ! " (with its spaces) and the sentence give DAMNIT ! SORRY…: the program adds no space between two arguments.
2With no argument, a fixed message. In main, argc == 1 means "no argument": argv[0] is the name of the program.
3A newline at the end. The subject requires it for every output (p. 3), including the noise message.

Uppercasing. std::toupper (header <cctype>) takes a character and returns its uppercase version, but as an int: sent as is to std::cout, it would print as a number (65 instead of A, checked). Convert it back to char before writing it. The C standard requires the argument to be representable as an unsigned char (or to be EOF): convert the character first, it is the safe case, especially for accented characters.

snippet · an idea, not the program
std::cout << static_cast<char>(std::toupper(static_cast<unsigned char>(c)));

The Makefile. The subject says the Makefile rules are the same as in C (p. 4); the exact rules are in the Norm, so reread it. A skeleton that compiles with c++, rebuilds nothing when nothing changed (checked by running make twice in a row) and provides all, clean, fclean and re:

Makefile
NAME     = megaphone
CXX      = c++
CXXFLAGS = -Wall -Wextra -Werror -std=c++98
SRC      = megaphone.cpp
OBJ      = $(SRC:.cpp=.o)

all: $(NAME)

$(NAME): $(OBJ)
	$(CXX) $(CXXFLAGS) $(OBJ) -o $(NAME)

%.o: %.cpp
	$(CXX) $(CXXFLAGS) -c $< -o $@

clean:
	rm -f $(OBJ)

fclean: clean
	rm -f $(NAME)

re: fclean all

.PHONY: all clean fclean re

For the next exercises, only the SRC list changes (and the NAME: the ex01 subject asks for "a relevant name" for the executable, p. 10). Careful: this rule does not depend on the .hpp files. If you modify a header, make recompiles nothing by itself (observed): run make re, or add your headers as dependencies of the %.o rule.

ex01 · My Awesome PhoneBook

A "1980s-style" phonebook (p. 9), on the command line. Files to turn in (p. 9), in ex01/: Makefile, *.cpp, *.{h, hpp}. The executable's name is free but must be relevant (p. 10).

Classes

PhoneBook and Contact

Two classes, and the phonebook must be an instance of PhoneBook, each contact an instance of Contact (p. 9). You are free to design them, with the public/private rule from the classes section.

Storage

8 contacts, no new

PhoneBook has an array of contacts, 8 at most. A 9th contact replaces the oldest one. Dynamic allocation is forbidden (p. 9).

ADD

Save a contact

The fields are entered one at a time: first name, last name, nickname, phone number, "darkest secret". No field can be empty (p. 10).

SEARCH

Display a contact

A list of 4 columns (index, first name, last name, nickname), then a prompt for an index, then the contact is displayed, one field per line. Wrong index: you define a relevant behavior (p. 10).

EXIT

Quit

The program quits and the contacts are lost. Any other input is ignored; after each command is executed, the program waits for another one (p. 10).

The headers. Here is one way to write them: declarations only, two classes, nothing more. The names are suggestions (the subject dictates no method name here).

Contact.hpp
#ifndef CONTACT_HPP
# define CONTACT_HPP

# include <string>

class Contact
{
public:
    void setFirstName(const std::string &value);
    void setLastName(const std::string &value);
    void setNickname(const std::string &value);
    void setPhoneNumber(const std::string &value);
    void setDarkestSecret(const std::string &value);

    const std::string &getFirstName(void) const;
    const std::string &getLastName(void) const;
    const std::string &getNickname(void) const;
    const std::string &getPhoneNumber(void) const;
    const std::string &getDarkestSecret(void) const;

private:
    std::string _firstName;
    std::string _lastName;
    std::string _nickname;
    std::string _phoneNumber;    // a std::string: an int would lose a leading 0
    std::string _darkestSecret;
};

#endif
PhoneBook.hpp
#ifndef PHONEBOOK_HPP
# define PHONEBOOK_HPP

# include "Contact.hpp"

class PhoneBook
{
public:
    PhoneBook(void);

    void add(void);             // the ADD command
    void search(void) const;    // the SEARCH command

private:
    Contact _contacts[8];       // a fixed array: no new
    int _count;                 // how many contacts are stored (0 to 8)
    int _next;                  // where to put the next one; when full: the oldest one's slot
};

#endif

The oldest is replaced in a circle. As long as the phonebook is not full, the contact goes into the first free slot. After that, it replaces the oldest one (not the last one added!). A position _next that advances by 1 and comes back to 0 after 7 (the computation (_next + 1) % 8) is enough: the first slot overwritten is 0, then 1, and so on.

The SEARCH display. Each column is 10 characters wide, right-aligned, and the columns are separated by | (p. 10). Text that is too long is truncated and its last visible character is replaced by a dot: for Alexandria-Long, you print Alexandri. (9 characters then the dot). Text of exactly 10 characters is left alone. The subject does not mention a bar at the start or the end of the line: that is your choice. Play with the demo, then read the equivalent code:

Demo (requires JavaScript): a form (first name, last name, nickname) that adds rows to a PhoneBook-style table, with 10-character columns right-aligned and separated by |. Any text longer than 10 characters is truncated to 9 characters followed by a dot. Next to it, the equivalent std::setw(10) code.

Example without JavaScript: the first name Alexandria-Long is displayed as Alexandri.; the first name Bob is displayed as Bob (7 spaces then Bob).

     Index|First Name| Last Name|  Nickname
         0|Alexandri.|       Bob|     Bobby

What the demo shows you, to reproduce yourself:

1Truncating is your job. Type Alexandria-Long as the first name: setw cut nothing, it is a substr(0, 9) followed by a dot that gives Alexandri.. The column is always exactly 10 characters.
2Padding is setw. Type Bob: setw(10) adds the 7 spaces on the left.
3Eight contacts, not nine. Add nine of them: the ninth takes the place of index 0, the oldest.
4An empty field is refused. Leave a field empty: the contact is not added, as the subject requires.

Step by step

A work order that avoids debugging everything at once. The breakdown is advice, not a requirement: the subject sets the files and the behaviors, not your organization.

1Set up the ground. One directory per exercise (ex00, ex01, ex02), a Makefile with c++ -Wall -Wextra -Werror -std=c++98, and a "hello" that compiles. From now on, never type using namespace.
2ex00 first. A single file. Make the subject's three examples work identically, comparing with diff if needed. It is the warm-up: argc/argv, a loop, std::toupper.
3ex01: draw before you code. Who knows what? Contact only knows how to store five strings. PhoneBook stores the contacts, picks the next slot and handles the ADD and SEARCH commands.
4ex01: Contact then ADD. Write the class with no logic, then the input of one field: a small function that reads with std::getline, asks again while the line is empty, and reports failure when the input is closed.
5ex01: SEARCH and main. Display the list first (demo above), then read the index and validate it. Finally the command loop, which stops on EXIT and at the end of the input.
6ex01: test with scripted input. printf 'ADD\nAda\n…' | ./phonebook (the shell's printf, not the one in your code) lets you replay a scenario. Also test ./phonebook < /dev/null and Ctrl-D at every prompt: it must neither loop nor crash.
7ex02: let the linker make the list. Compile tests.cpp without Account.cpp: the Undefined symbols name what the test calls (constructor, destructor, makeDeposit, makeWithdrawal, displayAccountsInfos, displayStatus, checked). The static accessors are not listed, but displayAccountsInfos needs them.
8ex02: in the log's order. The definitions of the static members, the constructor and the destructor, the accessors, then deposits and withdrawals, then the displays, and the timestamp last. Compare with the log by stripping the timestamp on both sides, for example with sed 's/^\[[^]]*\] //', then diff. Reminder: the order of the closed lines may legitimately differ (p. 12).

Classic pitfalls

⚠️

Truncating without breaking the alignment. Text longer than 10 characters becomes 9 characters + a dot = 10 in all. Text of exactly 10 characters stays intact; 012345678. for 11 characters (checked). Do not truncate to 10 and then add a dot: you would have 11 characters and everything shifts. Do not forget that setw never cuts and only applies to the next item.

⚠️

Accented characters count double. std::string and setw count bytes. In UTF-8, ü weighs 2: setw(10) << "ü" writes 8 spaces and the column looks like 9 characters; a name made of six ü (12 bytes) is cut at 9 bytes, in the middle of a character (checked). The subject says nothing about this: own your choices (for example accept only ASCII) and be ready to explain them.

⚠️

std::cin and end of file (Ctrl-D). When the input closes, std::getline fails, and it fails on every following call. A while (1) loop that does not test the return value spins forever on empty commands; if the input ends without a trailing newline (printf 'ADD' | ./phonebook), the string even keeps its last value and the program replays ADD endlessly (checked). Always test if (!std::getline(std::cin, s)) and quit cleanly. Try < /dev/null and Ctrl-D at every prompt: at the start of a line, Ctrl-D closes the input in a terminal (checked).

⚠️

Empty input refused. "A saved contact can't have empty fields" (p. 10): ask for the field again, or cancel the ADD. But an "ask again while it is empty" loop must also exit when the input is closed, otherwise it spins forever (checked). The subject says nothing about a field filled with spaces: empty() considers it non-empty, so it is up to you. As for commands: only ADD, SEARCH and EXIT are accepted, any other input is ignored (p. 10).

⚠️

Out-of-range index. Read the index as a line (std::getline), then validate it yourself: empty, not a digit, negative, greater than 7, or valid but in a slot that is still empty. With std::cin >> index, an input such as abc puts the stream in a failed state and leaves the text in the buffer: every following read fails until you call std::cin.clear() and discard the line (checked). Do not confuse "index 0" with "not a number" if you use atoi, which returns 0 in both cases.

⚠️

std::getline after std::cin >>. std::cin >> n stops before the newline and leaves it in the buffer: the next std::getline reads an empty line (checked). The simplest fix: use only std::getline, including for commands and the index.

⚠️

Eight contacts maximum. The array is fixed (new is forbidden here, p. 9). The 9th contact replaces the oldest, not the last one added. Test by adding 9 then 10 contacts, then display the list: indexes 0 and 1 must be the two new ones, and SEARCH must only show filled slots.

⚠️

The log timestamp. You need padding zeros: without them, November 8, 2026 at 20:40:28 would be written 2026118_204028 instead of 20261108_204028 (checked). With std::setfill('0'), be careful: the fill is sticky. After it, a setw(5) << "Bob" writes 00Bob (checked); put std::setfill(' ') back or prefer std::strftime. And remember that the log differs from yours by its timestamps only (p. 12).

⚠️

Compilation pitfalls. std::toupper needs <cctype>: on clang/macOS, a program that only includes <iostream> compiles anyway, but nothing guarantees it elsewhere (to check with your school's compiler). A static member never defined, or defined in the header, breaks linking. An initialization list in the wrong order is an error with -Werror. An implementation in a .hpp or a missing include guard is worth 0 (p. 4).

11

How I did it

For megaphone, I walk through the arguments character by character, turn each letter into uppercase, and add nothing between arguments; with no argument, I print the noise message. In the PhoneBook, Contact holds only five private strings with their accessors. PhoneBook keeps an array of eight contacts, the number of stored contacts and the position of the oldest one, which advances in a circle once the phonebook is full. I read everything with getline, in a small function that asks again while the input is empty and stops cleanly if the input closes. The display combines setw(10) with a cut to nine characters followed by a dot. For Account, I read the log line by line to deduce each method, then I built the timestamp with setw and setfill.
